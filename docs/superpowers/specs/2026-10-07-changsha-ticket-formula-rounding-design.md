# 长沙动趣门票台账公式调整设计

## 背景与目标

长沙动趣王国门票台账当前已经有抖音、美团、携程三平台专属计算路径，但本次确认了三项新口径：

- 美团服务商到账只取应付金额，不再加技术服务费。
- 携程服务商到账继续取结算价金额。
- 抖音服务商佣金中的“订单实收 × 服务商佣金率”必须按每一条有效明细分别四舍五入到分，再汇总并计入三类带符号费用。

本次只调整 `scenic_id = changsha-dongqu` 的门票算法，不修改其他景区、酒店台账、接口字段或景区配置费率。

## 已确认业务口径

### 有效明细范围

- 美团继续只统计“结算方式 = 消费结算”的有效行。
- 携程继续只统计“流水类型 = 订单成本”的有效行。
- 抖音继续沿用长沙现有有效行识别和五项金额列校验。

### 美团公式

设整期应付金额合计为 `P`，景区配置核销率为 `Rh`，结算率为 `Rs`：

1. 服务商到账 = `P`。
2. 服务商佣金 = `0`。
3. 出版应得到账 = `P`。
4. 景区核销金额 = 四舍五入到分(`P × Rh`)。
5. 结算金额 = 四舍五入到分(`P × Rs`)。
6. 服务费 = 四舍五入到分(结算金额 − 景区核销金额)。

技术服务费列无论存在与否都不参与长沙美团计算；缺少技术服务费不得阻止解析。缺少应付金额仍应返回明确错误。遵义动物园继续使用“应付金额 + 技术服务费”，不受本次调整影响。

### 携程公式

设整期有效订单成本行的结算价金额合计为 `C`：

1. 服务商到账 = `C`。
2. 服务商佣金 = `0`。
3. 出版应得到账 = `C`。
4. 景区核销金额 = 四舍五入到分(`C × Rh`)。
5. 结算金额 = 四舍五入到分(`C × Rs`)。
6. 服务费 = 四舍五入到分(结算金额 − 景区核销金额)。

### 抖音公式

长沙抖音服务商到账公式保持现状。每一条有效明细的原始值记为：

- `Oi`：第 `i` 行订单实收。
- `Si`：第 `i` 行软件服务费。
- `Di`：第 `i` 行达人服务费。
- `Li`：第 `i` 行团长服务费。
- `Mi`：第 `i` 行平台撮合服务费。
- `Rc`：景区配置中的服务商佣金率。

Excel 中正常费用通常为负数，退款或冲正费用为正数。系统保留原始符号：正常负数降低佣金，正数冲正反向增加佣金。

整期计算顺序为：

1. 服务商到账 = `Σ(Oi + Si + Di + Li + Mi)`。
2. 每行订单佣金 = 四舍五入到分(`Oi × Rc`)。
3. 自动服务商佣金 = 四舍五入到分(`Σ每行订单佣金 + ΣDi + ΣLi + ΣMi`)。
4. 若业务复核手工修改服务商佣金，以手工值替代自动值。
5. 出版应得到账 = 四舍五入到分(服务商到账 − 服务商佣金)。
6. 景区核销金额 = 四舍五入到分(出版应得到账 × `Rh`)。
7. 结算金额 = 四舍五入到分(出版应得到账 × `Rs`)。
8. 服务费 = 四舍五入到分(结算金额 − 景区核销金额)。

软件服务费只影响服务商到账，不参与服务商佣金。达人、团长和平台撮合服务费按原始带符号金额参与服务商佣金。

## 快照与重算设计

当前逐日快照只保存每日订单实收合计，无法在修改佣金率后重现“每行先舍入”的结果。采用兼容扩展方案：

1. 长沙抖音解析每一条有效明细时，将该行订单实收追加到当日 `commission_order_rows` 列表。
2. `daily_json` 使用紧凑字段 `co` 保存该列表，列表元素使用十进制字符串，避免浮点误差。
3. 上传预览、首次保存、修改费率、手工修改佣金和再次编辑统一调用公共计算器。
4. 计算器发现长沙抖音快照含 `co` 时，逐元素执行 `订单实收 × 佣金率` 并分别保留两位，再汇总。
5. 历史快照没有 `co` 时保持兼容，回退到现有整期订单实收乘佣金率的算法，不报错、不破坏历史台账读取。
6. 已上传的旧台账无法从每日合计反推出逐行舍入结果；必须重新上传原始对账文件后，才会完整应用新口径。

新增字段只存在于门票台账内部逐日 JSON，不改变外部 API schema 或前端表单。

## 实现边界

- 长沙美团不再使用 `amount_plus_tech_fee` 策略；遵义美团继续使用该策略。
- 长沙携程解析与有效行过滤保持不变。
- 长沙抖音服务商到账、必要列校验、平台撮合列别名、手工佣金覆盖和整期核销/结算路径保持不变。
- 不修改长沙核销率、结算率和佣金率配置。
- 不迁移或重写已有数据库台账；旧快照通过兼容分支继续可读、可编辑。
- 不改变鹳雀楼、泉城欧乐堡、南阳动物园、遵义动物园及其他景区算法。

## 错误处理

- 长沙美团缺少应付金额时报错；缺少技术服务费不报错。
- 长沙携程缺少结算价金额时报错。
- 长沙抖音继续要求订单实收、软件服务费、达人服务费、团长服务费和平台撮合服务费五项金额列。
- `co` 缺失或不是列表时按历史快照处理；列表内无法转换的单个值按现有金额解析规则归零，避免旧数据导致接口异常。
- 空行和小计行继续按现有规则跳过；有效的零金额、负数退款和正数冲正保留。

## 测试与验收

自动化测试覆盖：

1. 两笔临界小额订单证明逐行舍入与整期舍入的结果不同，并断言采用逐行结果。
2. 正常负费用降低佣金，正数冲正反向增加佣金。
3. 修改佣金率后，使用 `co` 中逐行订单实收准确重算。
4. 手工服务商佣金仍覆盖自动佣金。
5. 旧快照没有 `co` 时使用兼容回退且结果稳定。
6. 长沙美团技术服务费存在时被忽略，缺失时仍可解析，应付金额之外的值不进入到账。
7. 长沙携程继续只计订单成本行并使用结算价金额。
8. 遵义美团仍要求并计入技术服务费，其他景区回归结果不变。
9. 逐日 JSON 的 `co` 序列化、反序列化和再次编辑重算一致。

完成自动化测试后，使用此前提供的长沙实际 Excel 做只读验收。抖音金额按新的逐行舍入公式重新计算，不沿用旧设计中的整期佣金结果；美团和携程分别按本设计的新基数核对。实际文件不复制到仓库、不提交 Git。
