# 长沙动趣门票台账专属公式设计

## 背景

长沙动趣王国上传文件 `长沙动趣9.11-9.20(1).xlsx` 同时包含抖音、美团、携程三个工作表。现有通用门票解析器能够识别三个平台，但存在以下差异：

- 抖音通用规则未独立保存“平台撮合服务费”，无法在修改佣金率后完整重算长沙佣金。
- 美团当前按“应付金额”计算，长沙要求复用遵义动物园的“应付金额 + 技术服务费”规则。
- 当前通用计算器逐日取整，长沙要求整期汇总后统一四舍五入到分。
- 长沙现有默认费率为核销率 90%、结算率 94%、佣金率 6%，本次需更新为 93%、96%、18%。

本设计仅修改 `changsha-dongqu` 门票台账，不改变其他景区和酒店台账。

## 已确认业务口径

### 账单符号

抖音账单的正常费用为负数，退款或冲正费用为正数。系统保留 Excel 原始符号并直接参与加总，不对每一行取绝对值。

设整期汇总值如下：

- `O`：订单实收金额。
- `S`：软件服务费。
- `D`：达人服务费。
- `L`：团长服务费。
- `M`：平台撮合服务费；同时兼容表头“撮合经纪服务费”。
- `Rc`：景区配置中的服务商佣金率。
- `Rh`：景区配置中的核销率。
- `Rs`：景区配置中的结算率。

### 抖音公式

所有公式先汇总整期原始值，再按顺序计算：

1. 服务商到账金额 = `O + S + D + L + M`。
2. 自动服务商佣金 = 四舍五入到分(`O × Rc + D + L + M`)。
3. 若业务复核手工修改服务商佣金，则以手工金额替代自动服务商佣金。
4. 出版应得到账 = 四舍五入到分(服务商到账金额 − 服务商佣金)。
5. 景区核销金额 = 四舍五入到分(出版应得到账 × `Rh`)。
6. 结算金额 = 四舍五入到分(出版应得到账 × `Rs`)。
7. 服务费 = 四舍五入到分(结算金额 − 景区核销金额)。

软件服务费只影响服务商到账，不参与服务商佣金公式。达人、团长、平台撮合三项带符号费用同时影响服务商到账和服务商佣金。

### 美团公式

长沙美团完全复用遵义动物园规则：

- 只计入“消费结算”行。
- 服务商到账和出版应得到账 = 整期汇总(`应付金额 + 技术服务费`)。
- 服务商佣金固定为 0。
- 核销金额、结算金额和服务费按整期出版应得到账及长沙配置费率计算。

### 携程公式

长沙携程完全复用遵义动物园规则：

- 只计入“流水类型 = 订单成本”的行。
- 服务商到账和出版应得到账 = 整期“结算价金额”汇总。
- 服务商佣金固定为 0。
- 核销金额、结算金额和服务费按整期出版应得到账及长沙配置费率计算。

## 景区费率配置

长沙动趣王国门票配置更新为：

| 配置项 | 数值 |
| --- | ---: |
| 核销率 | 93% |
| 结算率 | 96% |
| 服务商佣金率 | 18% |

代码内景区种子默认值与生产数据库实际配置必须同时更新。数据库迁移使用景区 ID `changsha-dongqu` 定位并幂等更新，不影响其他景区，也不覆盖景区名称、排序、默认门票产品等无关字段。

上传解析始终读取景区配置快照，不在公式分支内写死费率。后续在景区配置中修改费率时，保存后的逐日快照仍能按新费率重算。

## 解析与计算架构

采用长沙动趣专属策略，不修改通用抖音规则：

1. 门票解析器通过 `scenic_id + platform` 选择长沙规则。
2. 长沙抖音要求订单实收、软件、达人、团长和平台撮合五项金额列；平台撮合列接受“平台撮合服务费”或“撮合经纪服务费”。
3. 解析器按日期保存已计算的服务商到账、订单实收、达人费、团长费和平台撮合费，并写入 `changsha_douyin` 计算模式标记。
4. 逐日 JSON 新增平台撮合费用字段；旧 JSON 缺少该字段时按 0 读取，保持历史台账兼容。
5. 公共计算器仅在 `scenic_id = changsha-dongqu` 时启用整期取整路径。抖音按整期汇总佣金，美团和携程按整期基数计算核销与结算。
6. 上传预览、首次保存、修改费率、手工修改佣金和再次编辑均调用同一计算器，避免预览与落库结果不一致。

没有逐日 JSON 的历史或手工台账继续走现有期级兜底：使用已保存的服务商到账和手工佣金计算出版应得、核销、结算及服务费。

## 输入校验与异常处理

- 长沙抖音缺少任一必要金额列时，上传失败并列出具体缺失表头。
- 长沙美团缺少技术服务费时，沿用遵义动物园的明确错误提示。
- 无法解析的空行、小计行不计入；有效金额为 0 的明细保留。
- 退款和冲正按原始金额及费用符号计入，不把负数强制转正。
- 文件包含无法识别的平台工作表时，保持现有行为：忽略该工作表，不生成台账行。
- 本次不增加前端字段、不改变接口结构、不修改酒店算法。

## 测试策略

自动化测试使用代码生成的最小 Excel，覆盖：

- 抖音五项金额列、非零平台撮合费、正常负费用和正数冲正。
- 抖音整期佣金取整、出版应得、核销、结算和服务费。
- 修改佣金率后的逐日 JSON 重算。
- 手工服务商佣金覆盖自动佣金。
- 旧逐日 JSON 没有平台撮合字段时按 0 兼容。
- 抖音必要列缺失时的字段级错误提示。
- 美团复用遵义的应付金额加技术服务费规则。
- 携程复用遵义的订单成本流水过滤规则。
- 遵义动物园和其他景区现有结果不变。
- 景区种子默认值与数据库迁移只更新长沙动趣三项门票费率。
