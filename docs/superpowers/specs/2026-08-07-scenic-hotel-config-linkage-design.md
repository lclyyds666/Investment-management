# 景区酒店配置联动设计

日期：2026-08-07

## 目标

景区酒店台账的新上传解析应按 `scenic_id` 读取 `biz_scenic_config` 中已经持久化的核销率、结算费率和服务商佣金率。运营人员修改景区配置后，下一次酒店上传使用修改后的默认值；已经打开的草稿和历史台账继续保留各自快照。

## 设计选择

复用现有景区配置中的 `ticket_rate_hexiao`、`ticket_rate_settle` 和 `ticket_commission_rate` 作为该景区文旅台账的统一默认费率，不新增酒店专用配置列。这样前端仍只有一组核销率、结算费率和佣金率，不增加容易产生冲突的双份配置。

酒店的固定平台公式、每间夜服务费和算法选择不进入景区配置。本次不修改历史数据，不自动重算已经保存的台账。

## 数据流

1. 酒店解析接口按 URL 中的 `scenic_id` 读取最新有效景区配置。
2. 接口将景区标识、核销率、结算费率和佣金率显式传给酒店解析器。
3. 解析器按现有平台公式计算到账和佣金，并在每个平台解析结果中返回本次费率快照。
4. 前端草稿使用解析结果中的费率，不再使用 `0.90`、`0.94`、`0.06` 本地常量。
5. 保存请求透传草稿费率，后端继续将这些值随台账行持久化。

## 公式边界

- 福州欧乐堡抖音到账公式保持不变：存在“服务商服务费/服务商佣金”列时取该列相反数，否则按订单实收加软件、达人和团长费用列计算。
- 抖音服务商佣金保持为订单实收乘佣金率，再加明细中的达人和团长费用列；明细费用列为负数时等价于扣减。
- 酒店结算基数、核销金额、算法 1 和算法 2 的现有计算逻辑保持不变。
- 公式不通过景区配置接口暴露，也不允许前端修改。

## 兼容与错误处理

已知景区缺少持久化配置时继续使用现有种子配置；未知景区继续使用系统兜底。解析响应中的费率为必填快照，防止前端静默回落到另一组常量。

## 验收

- 福州欧乐堡当前生产配置 `91%/95%/8%` 能进入酒店解析结果和新保存台账。
- 修改景区配置后，下一次酒店解析采用修改值。
- 福州抖音到账和佣金公式保持不变。
- 门票解析、历史酒店计算和现有台账不发生回归。
- 后端测试、前端测试与生产构建全部通过。
