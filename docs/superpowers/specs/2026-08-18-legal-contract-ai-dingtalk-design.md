# 法务合同管理、AI 审查与钉钉预警设计

## 目标

在山东出版投资有限公司的法务风控应用中增加“合同管理”入口，向具备合同权限的法务人员提供供应链公司现有合同管理模块的完整能力，包括合同列表、详情、审批流、附件、合同台账、AI 审查和法规知识库。同时启用生产环境 DeepSeek 合同审查与法务钉钉预警。

## 方案比较

1. **复用现有合同域和页面（采用）**：法务入口与供应链入口共享同一合同数据、工作流、附件、AI 审查和法规库，仅增加路由、导航和权限校验。优点是数据一致、修复同步、没有双份业务逻辑。
2. **复制前后端代码**：创建第二套页面和 API，但仍访问同一表。短期直观，长期会产生行为、权限和安全修复漂移。
3. **建立投资公司独立合同域**：新增合同表、附件目录、工作流和知识库隔离。隔离最彻底，但改变了“复制供管公司合同管理模块”的数据口径，不在本次范围。

## 架构

- 法务路由新增 `/investment/legal-risk/contracts`，组件继续使用 `frontend/src/views/contract/index.vue`。
- 法务侧导航在“案件管理”之后显示“合同管理”。入口同时要求投资公司法务资源权限和 `supply.contract.view`，避免向无合同权限人员暴露敏感合同数据。
- 后端继续使用现有 `/api/v1/contracts`、`/api/v1/knowledge`、`biz_contract`、`biz_knowledge_doc` 和 `supply.contract.v2` 工作流，不复制模型或表。
- 供应链入口与法务入口看到的是同一份合同数据和法规库；任一入口产生的审批、附件和 AI 审查依据完全一致。

## 前端行为

- `InvestmentLayout` 根据法务资源和合同查看权限过滤“合同管理”菜单；移动端抽屉同步显示。
- 路由守卫同时校验投资公司应用访问、法务资源和合同权限。
- 合同页面保持现有新建、编辑、删除、提交、审批、退回、附件预览/下载、合同台账、AI 审查和法规知识库功能，按钮继续按现有细粒度权限显示。
- AI 审查 Markdown 使用项目统一的安全渲染函数，禁止模型输出注入 HTML、链接、图片或事件属性。

## AI 审查与法规知识库

- DeepSeek 使用现有 OpenAI 兼容客户端、`deepseek-chat` 模型和规则引擎降级策略。
- 合同附件可提取文本时优先审查附件全文；否则审查结构化合同字段。
- AI 自动聚合现有法规知识库文本并在结果中返回实际引用的文件标题。
- 法务入口沿用供应链合同的委托审查方立场，不改变现有供应链合同审批口径。
- `DEEPSEEK_API_KEY` 只写入生产 `/opt/sd-scm/backend/.env`，不进入代码、文档、测试、日志或 Git 历史。

## 权限与安全

- 合同列表和详情继续遵守现有公司范围与外聘法律顾问“仅被指定合同”的数据范围。
- AI 审查、附件下载和法律文件下载必须在执行前调用同一合同可见范围校验，禁止通过猜测合同 ID 越权访问。
- 法规知识库继续使用合同查看/维护权限；上传文件类型、大小和文本提取规则保持不变。
- API 错误沿用现有统一响应；DeepSeek 不可用时返回规则引擎结果，不让合同页面因模型故障不可用。

## 钉钉预警

- 复用已上线的法务预警扫描、重试、投递记录、签名 Webhook 和手机号 `@` 能力，不新建第二套通知任务。
- 生产配置启用 `DINGTALK_LEGAL_ALERT_ENABLED`，写入 Webhook 与签名 Secret，并重启后端使配置生效。
- 部署后通过现有 `DingTalkClient.send_test` 发送一条最小披露测试消息，确认签名和机器人返回成功。
- 钉钉凭据只保存在生产 `.env` 与受限备份中，不进入 Git 或发布包。

## 测试与发布

- 前端覆盖法务合同路由、导航权限过滤、活动菜单和 AI Markdown 安全渲染。
- 后端覆盖合同 AI 审查、附件和法律文件的数据范围校验，并保留现有合同、知识库和钉钉测试。
- 运行后端全量测试、前端全量测试和生产构建；代码审查无阻断问题后提交到 `main`。
- 部署前备份数据库、合同/知识库/法务附件、当前后端、前端和 `.env`；部署后验证健康接口、法务合同页面、DeepSeek 实际响应、钉钉测试消息、预警定时器和回滚点。

## 非目标

- 不建立投资公司独立合同表或第二套审批流。
- 不修改现有合同审批节点、历史合同、审批数据或知识库内容。
- 不把任何用户提供的密钥写入仓库。
