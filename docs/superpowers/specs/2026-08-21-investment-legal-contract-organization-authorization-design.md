# 投资公司法务合同审批与组织权限改造设计

## 1. 背景与目标

山东出版投资有限公司及其部门、子公司统一通过投资公司法务风控平台办理合同和诉讼案件。供管公司平台不再单独提供合同管理入口。

本次改造目标如下：

1. 为投资公司其他部门、投资公司法务风控部、投资公司子公司建立三套合同审批流程。
2. 延续现有“提交审批后弹出指定审批链路”的交互，由发起人逐节点指定具体审批人员。
3. 新增山东展威科技有限公司、山东新华置业有限公司及指定岗位。
4. 调整现有岗位名称和岗位体系，消除旧的业务、财务、供应链风控岗位显示名称。
5. 供管公司、基管公司、展威科技可上传合同和诉讼案件；新华置业可上传诉讼案件。
6. 投资公司普通部门、各子公司只能查看与本部门或本公司相关的数据；投资公司法务风控部可查看全部合同和案件。
7. 岗位权限模板中的权限名称、岗位类别、数据范围、业务域和范围引用全部使用中文显示。

## 2. 范围与非目标

### 2.1 本次范围

- 合同审批工作流选择、候选人解析、提交校验和历史快照。
- 合同和诉讼案件的数据归属及后端访问控制。
- 投资公司法务风控平台合同入口和供管平台旧入口迁移。
- 组织、岗位、权限目录与生产数据迁移。
- 组织管理、岗位与权限、合同管理、案件管理相关前端页面。

### 2.2 非目标

- 不为诉讼案件新增审批工作流；案件只进行上传、维护和数据隔离。
- 不建设通用可视化流程设计器。
- 不改变已经启动的历史审批实例、历史节点名称或审批动作快照。
- 不物理删除已被任职、权限或历史工作流引用的岗位记录。

## 3. 总体架构

采用“统一法务平台 + 三套固定合同工作流 + 业务数据归属 + 后端强制范围过滤”的架构。

合同和案件在创建草稿时记录所属公司、发起组织和发起任职。合同提交时根据归属自动选择三套工作流之一。候选人接口读取合同归属，根据节点候选规则返回当前有效任职人员。发起人在指定审批链路弹窗中逐节点选择人员，后端在最终提交时重新校验任职、范围和人员唯一性。

数据可见性不依赖前端菜单。所有列表、详情、附件、导出、统计和写接口都使用相同的后端范围判断，防止通过修改 URL、请求参数或附件地址越权访问。

## 6. 合同审批流程

### 6.1 流程选择

合同提交时按发起组织自动匹配：

1. 发起组织为投资公司法务风控部：使用“法务风控部合同审批”。
2. 发起组织为投资公司其他部门：使用“投资公司部门合同审批”。
3. 所属公司为供管公司、基管公司或展威科技：使用“子公司合同审批”。
4. 新华置业没有合同新建权限，不能进入合同提交。

单一有效发起任职时自动带出；存在多个可发起任职时，用户在创建草稿时必须选择发起组织。发起归属在草稿保存后固定，只有草稿创建人或超级管理员可在首次提交前修改。

### 6.2 投资公司其他部门流程

| 顺序 | 页面显示名称 | 候选人规则 |
| --- | --- | --- |
| 1 | 经办部门负责人 | 发起部门内有效任职的部门主任 |
| 2 | 外聘法律顾问 | 服务范围包含合同法律审查且在有效期内的外聘法律顾问 |
| 3 | 法务风控部 | 投资公司法务风控部内具备合同审核权限的有效任职人员 |
| 4 | 分管领导 | 对发起部门具有治理范围的投资公司分管领导 |
| 5 | 总经理 | 投资公司总经理有效任职人员 |
| 6 | 单位主要负责人 | 投资公司董事长有效任职人员 |

“经办部门负责人”和“单位主要负责人”是工作流节点显示名称；候选人的实际岗位名称分别为“部门主任”和“董事长”。

### 6.3 子公司流程

| 顺序 | 页面显示名称 | 候选人规则 |
| --- | --- | --- |
| 1 | 公司负责人 | 发起子公司内具备公司负责人权限的有效任职人员 |
| 2 | 外聘法律顾问 | 服务范围包含合同法律审查且在有效期内的外聘法律顾问 |
| 3 | 法务风控部 | 投资公司法务风控部内具备合同审核权限的有效任职人员 |
| 4 | 分管领导 | 治理范围包含发起子公司的分管领导 |

供管公司的公司负责人岗位显示为“供管公司负责人”。基管公司和展威科技按照各自负责人岗位匹配。流程表统一显示“公司负责人”。

### 6.4 法务风控部流程

| 顺序 | 页面显示名称 | 候选人规则 |
| --- | --- | --- |
| 1 | 经办部门负责人 | 法务风控部内有效任职的部门主任 |
| 2 | 外聘法律顾问 | 服务范围包含合同法律审查且在有效期内的外聘法律顾问 |
| 3 | 分管领导 | 对法务风控部具有治理范围的投资公司分管领导 |
| 4 | 总经理 | 投资公司总经理有效任职人员 |
| 5 | 单位主要负责人 | 投资公司董事长有效任职人员 |

### 6.5 指定审批链路交互

- 点击“提交审批”后打开指定审批链路弹窗。
- 弹窗展示本合同自动匹配的流程名称、发起组织和完整节点顺序。
- 每个节点均从后端返回的有效候选人中选择一名具体人员。
- 同一人员不能承担同一审批实例的两个节点，发起人也不能选择自己承担后续节点。
- 候选人为空、加载失败或任职已失效时，提交按钮不可用。
- 最终提交时后端重新校验候选人资格；资格变化返回明确错误，前端保留弹窗并重新加载候选人。

## 7. 合同与案件归属

合同和案件增加以下归属字段：

- `company_code`：所属公司编码。
- `organization_code`：发起部门或发起子公司编码。
- `initiator_assignment_id`：创建时选定的有效任职。

字段由后端根据当前用户有效任职校验，不能提交任意组织编码。超级管理员代录时也必须选择一个有效业务组织，不允许生成无归属数据。

### 7.1 创建权限

| 发起主体 | 合同 | 诉讼案件 |
| --- | --- | --- |
| 投资公司普通部门 | 可创建 | 可创建 |
| 投资公司法务风控部 | 可创建 | 可创建 |
| 供管公司 | 可创建 | 可创建 |
| 基管公司 | 可创建 | 可创建 |
| 展威科技 | 可创建 | 可创建 |
| 新华置业 | 不可创建 | 可创建 |
| 外聘法律顾问 | 不可创建 | 不可创建 |

### 7.2 查看范围

| 用户范围 | 可见数据 |
| --- | --- |
| 投资公司法务风控部 | 全部合同和案件 |
| 超级管理员 | 全部合同和案件 |
| 投资公司其他部门 | `organization_code` 等于本人有效任职部门的数据 |
| 子公司人员 | `company_code` 等于本人有效任职公司的数据 |
| 外聘法律顾问 | 指定给本人的合同审批数据 |
| 其他指定审批人 | 本人审批待办或已参与审批的合同，以及原有组织范围内数据 |

同一用户存在多条有效任职时，可见范围取并集。列表、详情、附件、导出、统计、预警和写操作使用同一范围服务。

## 8. 权限体系

### 8.1 法务合同权限

新增法务合同权限资源，至少包含查看、新建、修改、删除、提交、审核、通过、退回和导出。新页面和接口只使用法务合同权限。旧 `supply.contract.*` 权限保留为历史兼容项，但不再授予新岗位，也不再显示供管平台合同入口。

### 8.2 法务案件权限

案件权限从单纯角色判断收敛到有效任职、岗位权限和数据范围。保留旧角色作为迁移期兼容输入，但最终授权结果必须由岗位权限和归属范围决定。

### 8.3 中文权限模板

权限目录为每个权限编码维护稳定的中文名称，例如“法务预警查看”“法务合同提交”“法务案件新建”。岗位与权限页面同时中文化：

- 岗位类别：高管、部门、业务、治理、外聘、职责。
- 数据范围：平台、公司、部门、业务域、本人创建、本人参与、指定给本人。
- 业务域：投资公司、供管业务、基管业务。
- 公司和部门范围引用：显示组织中文名称。
- 权限分组：显示中文资源名称，不直接显示英文资源编码作为组标题。

数据库权限编码保持英文，确保接口和历史授权稳定。

## 9. 前端导航与页面

- 投资公司法务风控右侧栏保留“合同管理”，使用统一合同页面。
- 供管公司侧栏删除“合同管理”。
- `/supplymanagement/contract` 及旧合同书签跳转到 `/investment/legal-risk/contracts`。
- 合同和案件新建表单增加“所属公司/发起组织”。仅有一个可选任职时只读显示；多个任职时显示必选下拉框。
- 合同列表和案件列表显示所属公司、发起组织，法务风控部可据此筛选。
- 新华置业用户不显示合同新建按钮，后端同时拒绝创建请求。

## 10. 数据迁移与兼容

### 10.1 业务数据回填

- 现有合同默认回填 `company_code=supplymanagement`、`organization_code=supplymanagement`。
- 现有案件默认回填 `company_code=investment`、`organization_code=investment.legal_risk`。
- 无法匹配有效任职的历史记录保留空的发起任职引用，但公司和组织归属必须完成回填。

### 10.2 工作流兼容

- 已启动的 `supply.contract.v2` 实例继续按原版本办理。
- 新合同提交使用三套新工作流定义。
- 历史任务、动作、岗位名称和签名快照不修改。
- 工作流目录播种幂等发布新版本，重复执行不会创建重复定义或重复版本。

### 10.3 岗位兼容

- 更新现有岗位显示名称，不修改已使用的内部编码。
- 新岗位采用独立编码。
- 目录播种会同步本次明确要求的组织和岗位名称；管理员自定义权限授予不被无条件覆盖。
- 迁移脚本生成变更报告，列出名称调整、新增岗位、权限迁移和无法自动确认的任职。

## 11. 错误处理

- 没有可用发起任职：禁止创建并提示联系管理员配置岗位。
- 多个可用发起任职未选择：返回字段校验错误。
- 所选发起组织不属于当前用户：返回权限错误。
- 工作流候选人为空：弹窗展示具体缺失节点，禁止提交。
- 所选审批人重复或包含发起人：返回节点级错误。
- 审批人任职在提交前失效：返回资格变化错误并要求重新加载。
- 跨范围访问合同、案件或附件：统一返回不存在或无权访问，不泄露目标数据详情。
- 旧流程实例继续调用旧工作流定义，不能因新目录发布而漂移。

## 12. 测试与验收

### 12.1 后端测试

- 三类发起组织分别匹配正确流程代码和节点顺序。
- 部门负责人、公司负责人、法务风控部、分管领导、总经理和董事长候选人范围正确。
- 同名岗位在不同组织之间不会串选。
- 多任职发起组织校验正确。
- 投资公司部门、四家子公司、法务风控部、外聘法律顾问、审批参与人和超级管理员的数据可见性矩阵正确。
- 合同和案件详情、附件、导出、统计及写接口均执行相同范围校验。
- 新华置业不能创建合同但可以创建案件。
- 旧工作流实例、旧合同和旧案件回填后仍可访问。
- 组织、岗位、权限和工作流播种重复执行结果一致。

### 12.2 前端测试

- 供管平台不再显示合同管理，旧地址正确跳转。
- 法务风控平台根据权限显示合同管理。
- 合同和案件表单正确处理单任职和多任职。
- 三套指定审批链路显示正确中文节点并提交指定人员映射。
- 权限模板所有用户可见标签均为中文。
- 新华置业隐藏合同创建操作。

### 12.3 完整验证

- 后端相关测试与完整测试通过。
- 前端相关组件测试、路由权限测试和完整测试通过。
- 前端生产构建通过。
- 数据库迁移在空库和已有数据副本上均可重复执行。

## 13. 发布顺序

1. 备份生产数据库和当前发布目录。
2. 部署兼容旧字段的后端代码。
3. 执行数据库结构迁移和业务数据回填。
4. 播种组织、岗位、权限和新工作流目录，审阅迁移报告。
5. 部署前端构建。
6. 执行组织权限、三套合同流程、四家子公司访问矩阵和旧数据回归验收。
7. 保留旧工作流定义和可回滚发布目录，不删除历史审批数据。
