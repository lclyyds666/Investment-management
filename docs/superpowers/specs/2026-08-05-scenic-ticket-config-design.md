# 景区门票配置与差异化解析设计

日期：2026-08-05

## 目标

景区门票台账解析不再直接使用系统默认常量 0.90、0.94、0.06，而是按
`scenic_id` 读取持久化的景区配置。配置修改后，后续新上传并解析的台账使用
修改后的默认值；已解析草稿保留解析时快照，已保存历史台账不自动重算。

## 配置边界

后端新增 `biz_scenic_config`，保存默认门票名称、核销率、结算费率、服务商
佣金率和默认服务商佣金。业务经办与信息维护可以修改，其他文旅查看角色只读。

服务商到账公式不属于运营配置。公式由后端根据景区和平台选择固定策略，不通过
API 返回，不在前端展示，也不允许前端修改。

## 初始配置

| 景区 | 默认门票名称 | 核销率 | 结算费率 | 佣金率 | 默认佣金 |
| --- | --- | ---: | ---: | ---: | ---: |
| 遵义动物园 | 遵义动物园 | 84% | 87% | 0% | 0 |
| 南阳森林野生动物世界 | 南阳森林野生动物世界 | 80% | 85% | 0% | 0 |

其他现有景区写入当前默认值，避免上线后行为变化。配置缺失时仅以系统常量兜底，
同时返回可诊断信息；兜底值不是正常业务数据源。

## 固定解析策略

- 遵义动物园抖音：服务商到账 = 订单实收 - 达人服务费 - 服务商服务费。
- 遵义动物园美团：服务商到账 = 应付金额 + 技术服务费。
- 南阳森林野生动物世界抖音：服务商到账 = 订单实收。
- 非抖音平台服务商佣金为 0。
- 其他景区和平台继续使用既有解析口径。

解析器按平台账单的实际正负号语义将费用归一后计算。特殊策略缺少必要列时应明确
报错，不得静默按 0 计算。

## 数据流

1. 前端上传账单到带 `scenic_id` 的解析接口。
2. 接口读取该景区最新配置，并将费率、默认佣金和景区标识显式传给解析服务。
3. 解析服务选择固定公式策略，计算各平台服务商到账和默认台账金额。
4. 解析响应携带本次生效的门票名称、核销率、结算费率、佣金率和默认佣金快照。
5. 前端草稿完全使用响应快照，不再使用 0.90、0.94、0.06 本地常量。
6. 保存时现有台账列持久化快照；以后修改景区配置不触碰该行。

## 前端

文旅业务首页新增“景区配置”按钮。弹窗列出景区及可编辑默认值；有编辑权限的角色
可逐行保存，其他角色只读。页面不显示任何公式、策略名或内部规则字段。

配置保存成功后再次打开显示数据库中的最新值。后续新上传解析立即使用新值；已经
打开的待确认草稿不被后台配置变化悄悄改写，需重新上传才能应用新配置。

## API 与权限

- `GET /scenic-spots/configs`：文旅查看角色查询全部配置。
- `GET /scenic-spots/{scenic_id}/config`：文旅查看角色查询单个配置。
- `PUT /scenic-spots/{scenic_id}/config`：业务经办与信息维护修改可编辑字段。

请求模型不包含公式策略字段。费率限制为 0 到 1，金额不得小于 0，门票名称去除
首尾空白且不能为空。写操作由现有审计中间件记录。

## 迁移与兼容

迁移只创建并初始化配置表，不更新 `biz_ticket_ledger`。现有台账模型列继续作为历史
快照。请求 Schema 中会覆盖配置的旧默认值改为可空，由服务端统一解析有效配置。

部署顺序为数据库迁移、后端、前端。后端在配置表缺失时可用兜底常量维持服务，
但生产发布必须先完成迁移。

## 验收

- 两个目标景区的新解析使用各自配置和固定平台公式。
- 修改配置后，下一次新解析使用修改值。
- 已解析草稿和历史台账不因配置变化自动改变。
- 其他景区继续保持现有默认值与解析结果。
- 无编辑权限角色不能修改配置。
- 后端解析、配置接口、历史回归测试和前端构建全部通过。
