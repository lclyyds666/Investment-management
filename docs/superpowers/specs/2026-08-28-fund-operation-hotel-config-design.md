# 资金管理、经营台账与酒店配置改造设计

## 1. 目标

本次改造交付四项相互关联的能力：

1. 将现有“建设中”的资金管理页改造成可持久化、可追溯的资金流水台账，自动计算资金余额并对 30 天内到期的授信和借款预警。
2. 在经营数据中心保留顶部四张指标卡、业务毛利润柱状图和毛利润占比环形图，并在页面尾部新增按景区展示的经营数据台账及合计行。
3. 将景区配置拆分为独立的门票配置和酒店配置，使酒店解析与计算不再复用门票参数。
4. 仅将资金管理、经营数据中心和战略总览的金额展示切换为万元；景区台账及其他现有业务页面不改单位。

## 2. 范围边界

### 2.1 本次包含

- 资金增加、资金使用的新增、查询、编辑、删除和结清操作。
- 可使用资金、累计增加、已使用资金、30 天内到期金额的自动汇总。
- 授信、借款的即将到期和已逾期预警。
- 经营数据中心按景区汇总的已投入业务规模、已实现业务规模、业务毛利润和资金占用时长。
- 景区经营数据台账合计行以及筛选联动。
- 酒店默认名称、费率、每间夜服务费、服务费算法和启用平台的独立配置。
- 酒店台账平台名称规范化为“抖音”“美团”“携程”，酒店品牌继续放在独立的酒店名称列。
- 资金管理、经营数据中心和战略总览的万元展示。

### 2.2 本次不包含

- 银行直连、自动获取银行余额或自动提款。
- 同程酒店对账单解析；酒店平台本轮只支持抖音、美团、携程。
- 修改门票、酒店、景区原始核销台账的元单位、导出单位或历史计算规则。
- 修改合同、审批、发票、法务、渠道等其他现有页面的金额单位。
- 修改正式打印件、原始附件、确认函中的人民币元及大写金额口径。
- 因景区配置变化自动重算历史台账。

## 3. 总体架构

后端继续以“元”作为金额存储和计算基准。资金管理新增独立资金流水模型和 REST 接口；经营数据继续只聚合门票与酒店台账；景区配置模型增加酒店专属字段。前端只在明确纳入本次范围的三个页面进行元与万元换算。

数据流如下：

1. 用户在资金管理页以万元录入，前端提交前乘以 10000，后端以元校验并持久化。
2. 后端根据全部资金流水计算资金汇总，并根据到期日和结清状态生成预警级别。
3. 经营接口从门票、酒店台账按景区和年份聚合经营指标，前端根据当前年份和景区筛选更新指标卡、图表与尾部台账。
4. 酒店上传解析读取当前景区的酒店配置快照，新生成台账保存该期参数；历史行继续使用自身快照。
5. 经营数据中心与战略总览收到的接口金额仍为元，组件展示前统一除以 10000。

## 4. 资金管理设计

### 4.1 资金流水模型

新增 `biz_fund_transaction`，一条记录代表一次资金增加或资金使用：

| 字段 | 含义 |
| --- | --- |
| `id` | 流水主键 |
| `direction` | `increase` 资金增加或 `usage` 资金使用 |
| `category` | 资金类型 |
| `amount` | 金额，数据库单位为元，必须大于 0 |
| `occurred_on` | 发生日期 |
| `counterparty` | 对方单位 |
| `summary` | 用途或摘要 |
| `maturity_date` | 到期日期，仅授信和借款必填 |
| `settlement_status` | `open` 未结清或 `settled` 已结清 |
| `settled_on` | 结清日期 |
| `remark` | 备注 |
| `created_by` | 创建人 |
| `created_at` / `updated_at` | 审计时间 |

资金增加类型限定为银行授信、公司借款、客户回款、自有资金、其他；资金使用类型限定为业务付款、费用支出、还本付息、其他。后端同时校验方向与类型组合，不能依赖前端选项防错。

授信或借款结清只停止到期预警，不直接冲减资金余额。实际偿还本金或利息必须同时登记一笔“还本付息”资金使用流水，保证余额变化有完整凭证。

### 4.2 汇总与预警

- 累计增加 = 所有 `increase` 流水金额之和。
- 已使用资金 = 所有 `usage` 流水金额之和。
- 可使用资金 = 累计增加 - 已使用资金，允许为负数以暴露资金缺口。
- 30 天内到期金额 = 未结清且到期日位于当前日期至未来 30 天内的银行授信、公司借款金额之和。
- 到期日早于当前日期且未结清的记录标记为已逾期。
- 到期日等于当前日期或未来第 30 天均纳入预警。

### 4.3 接口与权限

新增 `/funds` 路由：

- `GET /funds`：分页/筛选查询资金流水。
- `GET /funds/summary`：返回四项汇总及预警数量。
- `POST /funds`：新增流水。
- `PUT /funds/{id}`：编辑流水。
- `DELETE /funds/{id}`：删除流水。
- `POST /funds/{id}/settle`：结清授信或借款。

读取接口使用现有 `supply.finance.view` 权限；新增、编辑、删除和结清使用 `supply.finance.update` 权限。不存在的流水返回 404；非法金额、类型组合或日期返回明确的 422/400 错误。

### 4.4 页面

资金管理页顶部展示可使用资金、累计增加、已使用资金、30 天内到期金额，金额单位为万元。余额为负时使用风险色；即将到期和已逾期分别使用警告色和危险色。

下方使用一张资金流水台账，支持按方向、类型、结清状态、到期状态、日期范围和关键词筛选。新增/编辑弹窗以万元录入金额。银行授信、公司借款必须显示并校验到期日，其他类型允许不填。授信和借款记录提供“结清”操作。

## 5. 经营数据中心设计

### 5.1 页面结构

现有布局不删除、不替换：

1. 顶部保留已投入业务规模、已实现业务规模、已实现业务毛利润、资金占用时长四张指标卡。
2. 中部保留业务毛利润柱状图和毛利润占比环形图。
3. 页面尾部新增“景区经营数据台账”。

指标卡、图表和新增台账共用年份与景区筛选条件。金额卡片、图表坐标轴、提示框和新增台账均按万元显示；资金占用时长仍按天显示。

### 5.2 景区经营数据台账

每个景区一行，包含：

- 景区名称。
- 已投入业务规模。
- 已实现业务规模。
- 业务毛利润。
- 资金占用时长。

表尾增加合计行。三个金额字段直接求和；合计资金占用时长按净投入金额加权，不能对景区天数做算术平均。没有有效净投入的景区显示 `—`，不参与占用时长合计的权重。

### 5.3 聚合接口

扩展现有 `GET /operation/financial` 响应，增加可按景区和年份汇总的数据点。后端聚合仍只读取 `biz_ticket_ledger` 与 `biz_hotel_ledger`：

- 已投入业务规模 = 付款金额 - 跟投金额；同一酒店账期多个平台只计一次共享付款与跟投。
- 已实现业务规模 = 结算金额之和。
- 业务毛利润 = 服务费之和。
- 资金占用时长 = 净投入金额加权的付款日至回款日天数；未回款使用当前日期。

前端根据筛选后的聚合点同步计算四张指标卡、图表和景区台账。这样年份和景区筛选不会只影响图表而不影响顶部汇总。

## 6. 景区门票与酒店配置设计

### 6.1 配置模型

`biz_scenic_config` 保留现有门票字段，并增加酒店专属字段：

| 字段 | 含义 |
| --- | --- |
| `default_hotel_name` | 默认酒店名称 |
| `hotel_rate_hexiao` | 酒店默认核销率 |
| `hotel_rate_settle` | 酒店默认结算费率 |
| `hotel_commission_rate` | 酒店默认服务商佣金率 |
| `hotel_fee_per_night` | 每间夜服务费，单位元/间夜 |
| `hotel_fee_algo` | 默认算法：1 为间夜算法，2 为结算费率算法 |
| `hotel_platforms` | 启用平台，允许值仅为抖音、美团、携程 |

迁移为现有景区写入与当前酒店行为一致的默认值，避免上线后新解析结果变化。读取配置时继续保留缺表、缺行的系统兜底。

### 6.2 配置界面

“景区配置”弹窗使用“门票配置”“酒店配置”两个页签：

- 门票页签保留现有默认门票名称、核销率、结算费率、服务商佣金率和默认佣金。
- 酒店页签展示默认酒店名称、核销率、结算费率、服务商佣金率、每间夜服务费、默认算法和启用平台。
- 酒店每间夜服务费使用元/间夜，其余费率使用百分比。
- 每个景区单独保存，保存后只影响后续新解析。

### 6.3 酒店解析与台账

酒店解析、保存和旧客户端缺省参数路径均改为读取酒店专属配置，不再读取门票费率。每期台账继续保存费率、算法和每间夜服务费快照；修改配置不自动覆盖历史行。

酒店台账“平台”列直接显示 `row.platform`，仅允许规范名称“抖音”“美团”“携程”。酒店品牌继续显示在独立的“酒店名称”列。内部排序、原始明细恢复和分组仍使用“酒店名称 + 平台”联合键，避免不同酒店数据合并。

## 7. 单位规则

- 数据库和全部后端接口继续使用元。
- 资金管理输入与展示使用万元，提交前乘以 10000，回显前除以 10000。
- 经营数据中心所有金额展示使用万元。
- 战略总览全国、区域指标及地图金额提示使用万元。
- 景区门票台账、酒店台账、景区原始核销台账和对应导出继续使用元。
- 景区配置中的每间夜服务费继续使用元/间夜。
- 合同、审批、发票、法务、渠道等其他页面保持当前单位。
- 正式打印件、原始附件、确认函继续保持元及人民币大写。

万元换算只发生一次。前端提供可复用的 `yuanToWan`、`wanToYuan` 和万元格式化函数；调用端明确传入接口原始元值，禁止对已经转换的数据再次除以 10000。

## 8. 错误处理与兼容性

- 资金流水金额必须大于 0。
- 银行授信、公司借款必须填写到期日期；结清日期不能早于发生日期。
- 酒店费率必须位于 0 至 1，每间夜服务费不能为负，算法只能为 1 或 2，平台只能从三项允许值中选择。
- 迁移未执行时，景区配置只读路径继续使用系统默认值；写入路径要求先完成迁移。
- 酒店历史台账保留原参数快照，不批量重算。
- 经营指标无数据时金额显示 0.00 万元，占用时长显示 `—`；图表继续显示现有空状态。
- 资金汇总接口失败时保留页面错误提示，不用静态示例数据伪装成功。

## 9. 测试与验收

### 9.1 后端测试

- 资金增加、使用、负余额、编辑和删除后的汇总。
- 到期日为今天、第 30 天、第 31 天和已过期日期的边界。
- 结清后停止预警但余额不自动变化。
- 非法方向/类型组合、非正数金额和缺失到期日校验。
- 酒店配置的系统默认、持久化覆盖、独立费率和平台校验。
- 酒店解析、保存使用酒店配置，显式历史快照优先。
- 经营数据按景区、年份聚合，酒店同期共享投入去重，合计占用时长按净投入加权。

### 9.2 前端测试

- 元与万元正反向换算不重复、不丢失两位小数语义。
- 资金表单按万元提交、按万元回显，预警状态正确展示。
- 经营数据筛选同步影响指标卡、柱状图、环形图和尾部台账。
- 战略总览全国、区域和地图提示均显示万元。
- 酒店配置页签字段与提交载荷正确。
- 酒店台账平台列只显示平台名称，不拼接酒店名称。

### 9.3 回归验证

- 运行资金、经营聚合、景区配置和酒店台账相关后端测试。
- 运行相关 Vitest 测试和前端完整测试。
- 运行前端生产构建。
- 确认柱状图、环形图仍存在且筛选可用。
- 确认景区台账页面与导出仍以元为单位。
