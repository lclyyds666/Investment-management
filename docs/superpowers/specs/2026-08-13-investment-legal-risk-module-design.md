# 投资公司法务风控模块设计

## 1. 文档信息

- 版本：V1.0
- 日期：2026-08-13

- 后续兼容：复用同一套 API 接入微信小程序

## 2. 背景与目标

现有平台已具备 FastAPI、Vue 3、登录认证、公司级权限、附件存储、操作日志、Excel 处理和 systemd 部署能力，但投资公司入口仍为建设中页面，尚无诉讼案件独立数据域。诉讼案件与合同在对象、状态、当事人、执行资产、回款、期限和附件结构上差异显著，因此不将案件数据并入合同表。

本期目标如下：

1. 支持普通业务人员和法务风控人员创建案件草稿，信息完整后正式建档并进入案件全生命周期管理。
2. 统一维护案件基本信息、裁判结果、查扣冻资产、清回止损、进展风险、期限和材料。
3. 自动生成五类期限预警，通过站内提醒和钉钉法务预警群触达责任人。
4. 按案件状态、标的额、回款和预警形成可下钻、可导出的管理统计。
5. 按角色、参与关系、操作和案件状态控制数据访问，附件和导出全程留痕。
6. 提供标准 Excel 模板、导入预检和确认导入能力，为未来历史台账迁移保留安全入口。

## 3. 范围边界

### 3.1 本期范围

- 投资公司独立应用壳和侧栏导航。
- 法务工作台、诉讼案件、预警中心、统计分析。
- 案件草稿保存、正式建档和全生命周期维护。
- 案件全生命周期信息维护和逻辑归档。
- 多附件分类上传、预览、下载和删除。
- 五类自动预警、站内角标、站内弹窗和钉钉群机器人提醒。
- 标准 Excel 模板、导入预检、错误报告、确认导入和导出。
- 用户手机号和法务预警接收开关。
- 操作审计、权限校验、测试和生产调度配置。

### 3.2 本期不包含

- 微信小程序界面；仅保证 API 可复用。
- 短信通知。
- 外部法院、裁判文书或执行公开系统直连。
- AI 自动法律结论、胜诉概率或裁判预测。
- 未取得的历史 Excel 台账专用清洗规则。
- 独立微服务、对象存储和 WebSocket 推送。

## 4. 方案选择

采用“独立业务域、同一应用服务”方案：在投资公司子平台增加独立页面，在当前 FastAPI 服务中增加 `legal-risk` API 和独立数据表，复用认证、权限、附件、审计、Excel 和部署底座。

未采用以下方案：

- 扩展合同模块：短期代码量较少，但案件状态、多当事人、多附件、执行资产和预警会与合同审批强耦合。
- 独立微服务：隔离更强，但首期会重复建设登录、权限、附件、审计和部署能力，成本高于收益。

## 5. 总体架构

```text
投资公司 Web 应用
  ├─ 法务工作台
  ├─ 诉讼案件
  ├─ 预警中心
  └─ 统计分析
          │
          ▼
/api/v1/legal-risk
  ├─ 案件建档与生命周期服务
  ├─ 裁判/资产/回款/进展/期限服务
  ├─ 附件与导入导出服务
  ├─ 权限与数据范围服务
  ├─ 预警规则与统计查询服务
  └─ 钉钉通知适配器
          │
          ├─ MySQL 独立法务数据表
          ├─ 现有鉴权、用户、权限与审计底座
          ├─ 现有 uploads 文件存储
          └─ systemd timer 每日扫描与通知补偿
```

后端接口保持现有统一响应结构。Web 与未来小程序均调用资源型 API，不在接口中耦合 Element Plus 或桌面端交互状态。

## 7. 角色与数据范围

### 7.1 角色口径

首期兼容当前公司角色模型，以投资公司任职角色识别业务身份：

- `risk_auditor`：法务风控部人员。
- 投资公司管理层：董事长、总经理、副总经理，三类职务使用同一套法务管理层权限。当前公司角色模型尚未细分三类职务时，`invest_director` 作为管理层兼容角色。
- `legal_counsel`：外聘法律顾问。
- 其他具有投资公司有效任职的非超级管理员：普通业务人员，其法务模块权限与法务风控部人员完全相同。
- `is_superuser=true`：信息维护超级管理员。

后续统一组织岗位体系上线后，权限服务可将上述身份来源替换为有效岗位权限，不改变法务业务表和资源接口。

### 7.2 权限矩阵

| 能力 | 超级管理员 | 法务风控 | 董事长/总经理/副总经理 | 法律顾问 | 普通业务人员 |
| --- | --- | --- | --- | --- | --- |
| 查看案件及草稿 | 全部 | 全部 | 全部只读 | 被指派 | 全部 |
| 新建/编辑草稿 | 是 | 是 | 否 | 否 | 是 |
| 正式建档 | 是 | 是 | 否 | 否 | 是 |
| 修改案件基础信息 | 是 | 是 | 否 | 否 | 是 |
| 维护法律意见/进展 | 是 | 是 | 否 | 被指派案件 | 是 |
| 维护裁判/资产/回款/期限 | 是 | 是 | 否 | 否 | 是 |
| 上传材料 | 是 | 是 | 否 | 被指派案件 | 是 |
| 删除材料 | 是 | 是 | 否 | 仅本人上传且案件未归档 | 是 |
| 处理预警 | 是 | 是 | 否 | 被指派案件 | 是 |
| 归档/删除 | 是 | 是 | 否 | 否 | 是 |
| 查看统计 | 全部 | 全部 | 全部 | 否 | 全部 |
| 全量导入导出 | 是 | 是 | 管理报表导出 | 否 | 是 |

超级管理员按用户要求在首期拥有最大业务权限，用于测试和验收。其所有业务、附件、导入导出和预警操作仍写入审计日志。

普通业务人员与法务风控部人员复用同一组法务业务权限和全部案件数据范围。董事长、总经理、副总经理复用同一组管理层权限：全部数据只读、统计查看和管理报表导出，不直接修改案件业务数据。

### 7.3 鉴权顺序

后端按以下顺序判断：

```text
登录有效 → 投资公司准入 → 资源/操作权限 → 数据范围 → 对象状态 → 附件归属
```

前端菜单和按钮仅用于减少无效操作，后端接口是最终安全边界。未授权访问统一返回 403，不通过 404 差异泄露案件是否存在。

## 8. 案件草稿与正式案件流程

### 8.1 草稿建档

```text
新建草稿 ──持续补充──> 信息完整 ──正式建档──> 审查立案
```

- 普通业务人员、法务风控部人员和超级管理员均可创建、编辑和删除案件草稿。
- 草稿仅要求案件名称，允许先保存当事人、材料和其他已知信息。
- 草稿不生成正式案件编号，不进入案件状态统计，不触发期限预警或钉钉通知。
- 正式建档前必须具备案件名称、案由、受理法院、法院案号、标的额、负责人，以及至少一名原告和一名被告。
- 正式建档在同一事务中生成唯一案件编号、记录建档人和建档时间，并将案件主状态设置为“审查立案”。
- 正式建档后不可退回草稿；错误信息通过案件编辑和操作记录修正。

### 8.2 案件状态

案件主状态固定为：

1. 审查立案。
2. 审理中。
3. 已判决。
4. 执行中。
5. 终本。
6. 已结案。

主状态用于列表和统计。裁判层级、执行财产状态、资产处置状态不混入主状态字段。

案件编号在正式建档时由系统自动生成，格式为 `AJ-YYYY-NNNN`，按年份递增。法院案号作为独立字段，重复时提示现有记录，但允许有建档权限的人员确认保存，以兼容合并审理、不同审级和历史数据异常。

归档是“已结案”后的只读控制，不属于案件主状态。归档需满足：

- 主状态为“已结案”。
- 已填写结案日期和结案结果摘要。
- 不存在“待处理”或“处理中”预警。
- 操作者填写归档说明并二次确认。

归档后业务数据只读，具有案件查看权限的用户仍可预览和下载，导出继续按角色权限控制。解除归档仅超级管理员可执行并必须填写原因。

## 9. 案件详情结构

案件详情采用“顶部概览 + 标签页”结构。顶部固定展示案件编号、案件名称、主状态、负责人、标的额、累计回款、待回款、最近进展和下一关键期限。

| 标签页 | 字段与能力 |
| --- | --- |
| 基本信息 | 案件名称、案由、受理法院、法院案号、当事人、标的额、代理律所、代理律师、案情简介、诉讼请求、负责人、协同人、保密级别 |
| 裁判结果 | 一审、二审、再审、调解、和解的摘要、裁判或达成日期、生效日期、履行期限、可执行金额、当前执行依据 |
| 查扣冻资产 | 资产类型、名称或位置、措施类型、首封/轮候、开始日、到期日、剩余天数、处置状态 |
| 清回止损 | 回款或避免损失日期、类型、金额、来源说明、凭证；展示累计回款、待回款和避免损失金额 |
| 进展风险 | 最新进展、法律意见、风险点、下一步计划、责任人、计划完成日和跟进附件 |
| 期限事件 | 开庭、缴费/材料、自定义期限的事项、日期、提前量、负责人和完成状态 |
| 案件材料 | 判决书、调解书、裁定书、协助执行通知书、证据材料、回款凭证和其他材料 |
| 操作记录 | 建档、修改、状态变化、附件操作、预警处理、导入导出和归档记录 |

新增和编辑子记录使用抽屉或弹窗，不将所有字段堆叠为一个超长表单。

## 10. 数据模型

### 10.1 主数据表

`legal_case`：案件草稿与正式案件主表。

- 阶段字段：记录阶段（草稿/正式）、正式建档人、正式建档时间。
- 标识字段：案件编号、案件名称、案由、受理法院、法院案号；草稿阶段案件编号为空。
- 金额字段：标的额。
- 管理字段：主状态、负责人、保密级别、结案日期、结案结果摘要、归档时间、归档说明；草稿阶段主状态为空。
- 文本字段：代理律所、代理律师、案情简介、诉讼请求、执行财产状态。
- 并发与审计字段：版本号、创建人、创建时间、更新时间、逻辑删除时间。

`legal_case_party`：当事人。

- 字段：案件 ID、当事人类型（原告/被告/第三人）、名称、身份类型、证件或统一社会信用代码、联系方式、地址、排序。

`legal_case_collaborator`：案件协同人和法律顾问指派关系。

- 字段：案件 ID、用户 ID、参与类型（协同人/法律顾问）、生效时间、失效时间、指派人。

### 10.2 业务明细表

`legal_case_judgment`：裁判和调解结果。

- 字段：案件 ID、类型（一审/二审/再审/调解/和解）、摘要、裁判或达成日期、生效日期、履行期限、可执行金额、是否当前执行依据、排序。
- 同一案件最多一条记录标记为当前执行依据。

`legal_case_asset`：查封、冻结或扣押资产。

- 字段：案件 ID、资产类型、资产名称或位置、措施类型、顺位（首封/轮候）、开始日期、到期日期、处置状态、说明。
- 剩余天数由 `到期日期 - 当前日期` 实时计算，不落库。

`legal_case_recovery`：清回和避免损失明细。

- 字段：案件 ID、记录类型（回款/避免损失）、日期、金额、来源说明、登记人。
- 只有“回款”计入累计回款；“避免损失”单独汇总。

`legal_case_progress`：进展、风险和法律意见日志。

- 字段：案件 ID、记录类型（进展/法律意见）、进展内容、风险点、下一步计划、责任人、计划完成日、登记人、登记时间。
- 外聘法律顾问只能对本人被指派案件新增“法律意见”记录或授权范围内的进展记录。

`legal_case_deadline`：开庭、缴费/材料和自定义期限。

- 字段：案件 ID、事件类型、事项名称、事件日期、提前天数、责任人、完成状态、完成时间、完成说明。
- 查扣冻到期从资产表取数，申请执行从当前执行依据取数，终本月度监控从案件状态和终本日期取数，不重复存入期限表。

### 10.3 附件、预警和通知表

`legal_attachment`：统一法务附件。

- 字段：案件 ID、关联对象类型、关联对象 ID、附件分类、原文件名、存储名、扩展名、MIME、大小、SHA-256、上传人、创建时间、逻辑删除时间。
- 允许 PDF、DOC、DOCX、XLS、XLSX、PNG、JPG、JPEG。
- 单文件上限 50 MB。
- 预览优先支持 PDF 和常见图片；Word、Excel 提供鉴权下载，浏览器无法安全内嵌时不做伪预览。

`legal_case_alert`：一个业务事件周期对应一条可闭环预警。

- 字段：案件 ID、来源类型、来源 ID、预警类型、周期键、触发日期、截止日期、级别、责任人、状态、处理结果、完成或关闭时间。
- 唯一键：案件、来源类型、来源 ID、预警类型、周期键。

`legal_alert_delivery`：站内和钉钉的投递阶段与结果。

- 字段：预警 ID、渠道、阶段键、接收范围、尝试次数、状态、响应摘要、失败原因、首次发送时间、最后发送时间、下次重试时间。
- 唯一键：预警 ID、渠道、阶段键、接收范围。

`legal_case_activity`：案件业务操作记录。

- 字段：案件 ID、动作、对象类型、对象 ID、变更摘要、操作者 ID 与姓名快照、时间。
- 通用审计中间件继续记录请求路径、IP 和结果；业务操作表负责案件详情页可读的历史。

### 10.4 导入表

`legal_case_import_batch`：导入批次。

- 字段：文件名、文件哈希、模板版本、状态、总行数、可导入数、警告数、错误数、创建人、确认人、创建时间、确认时间。

`legal_case_import_row`：预检后的逐行映射结果。

- 字段：批次 ID、Excel 行号、规范化数据 JSON、校验状态、警告 JSON、错误 JSON、导入后案件 ID。

预检数据只允许批次创建者和具有全量导入权限的用户查看。未确认批次保留 7 天后由清理任务删除。

### 10.5 用户字段扩展

`sys_user` 增加：

- `mobile`：11 位中国大陆手机号，可为空，数据库中保存原值，普通界面仅返回脱敏值。
- `legal_alert_enabled`：是否接收法务钉钉 `@` 提醒，默认关闭。

仅超级管理员可维护这两个字段。

## 11. 金额与统计口径

- 累计回款：案件所有未删除且类型为“回款”的金额合计。
- 避免损失：案件所有未删除且类型为“避免损失”的金额合计。
- 应回款基数：当前执行依据的可执行金额；若尚无当前执行依据，则使用案件标的额。
- 待回款：`max(应回款基数 - 累计回款, 0)`。
- 状态占比：同一筛选条件下该状态案件数除以案件总数；总数为 0 时返回 0。
- 未处理预警：状态为“待处理”或“处理中”的预警数。
- 案件统计只包含记录阶段为“正式”的案件；草稿仅在案件列表通过“草稿”筛选查看。

列表、统计卡片、状态表、下钻和 Excel 导出调用同一查询构造器，避免重复实现统计口径。

## 12. 预警规则

### 12.1 默认规则

| 类型 | 来源 | 触发条件 | 默认提前量 |
| --- | --- | --- | --- |
| 查冻扣到期 | 资产 | 到期日进入提醒窗口 | 45 天 |
| 申请执行 | 当前执行依据 | 履行期限届满且待回款大于 0 | 到期即触发 |
| 开庭提醒 | 期限事件 | 开庭日期进入提醒窗口 | 45 天 |
| 缴费/材料期限 | 期限事件 | 截止日期进入提醒窗口 | 7 天 |
| 终本持续监控 | 案件 | 进入终本后按自然月提醒查询财产线索 | 每月一次 |

默认提前量由规则配置提供，资产或期限事件可在授权范围内覆盖提前天数。剩余天数始终实时计算。

### 12.2 生命周期和防重

一项业务事件只创建一条可处理的预警。投递阶段分为：

- `window-entry`：首次进入预警窗口。
- `due-date`：截止当天。
- `overdue-1`：逾期次日。
- `overdue-N`：此后每隔 7 天一次，直到预警完成或关闭。
- `terminal-YYYY-MM`：终本案件的自然月周期。

预警实例唯一键防止重复业务预警，投递唯一键防止同一阶段重复发送。修改来源日期后重新计算周期键；旧预警若尚未处理则自动关闭并注明“来源日期已变更”，再生成新周期预警。

### 12.3 状态闭环

预警状态为：待处理、处理中、已完成、已关闭。

- 开始办理可将预警置为“处理中”。
- “已完成”和“已关闭”必须填写处理结果。
- 完成或关闭后停止后续阶段提醒。
- 来源事项直接标记完成时，同一事务中完成对应预警。

## 13. 调度与钉钉通知

### 13.1 调度方式

- 每天 09:00 由独立 `systemd timer` 执行全量预警扫描和当天投递。
- 新增或修改期限、资产到期日、履行期限或案件终本状态后，同步计算业务预警；事务提交后通过后台任务尝试立即投递。
- 独立补偿任务每 5 分钟处理到期的失败投递，避免 API 进程重启造成消息丢失。
- 不在 Uvicorn 双 worker 中启动常驻调度器，避免多 worker 重复扫描。
- 超级管理员可在页面执行“立即扫描”和“发送测试消息”。

### 13.2 钉钉机器人配置

生产环境变量：

- `DINGTALK_LEGAL_ALERT_ENABLED`
- `DINGTALK_LEGAL_ALERT_WEBHOOK`
- `DINGTALK_LEGAL_ALERT_SECRET`
- `LEGAL_ALERT_TIMEZONE=Asia/Shanghai`

Webhook 和加签密钥不写入数据库、源码或日志。服务使用时间戳和 HMAC-SHA256 生成钉钉加签参数。

### 13.3 消息内容

钉钉消息只包含：

- 案件编号。
- 预警类型。
- 截止日期。
- 剩余或逾期天数。
- 责任人姓名。
- 登录系统查看详情的提示。

消息不包含当事人、案情、标的额、回款金额、风险正文或附件链接。

固定法务预警群内所有成员均可看到群消息。系统使用责任人的手机号执行 `@`；责任人未填写手机号或关闭法务预警接收开关时仍发送群消息，但不 `@`。

### 13.4 失败处理

- HTTP 超时、网络错误、钉钉非成功响应均记为失败。
- 首次发送失败后最多重试 3 次，重试间隔为 5 分钟、30 分钟、120 分钟。
- 发送失败不回滚预警生成或用户业务操作。
- 超过重试次数后标记“发送失败”，站内预警继续有效，超级管理员可手工重发。
- 未配置钉钉时标记“渠道未配置”，不视为预警生成失败。

## 14. 站内提醒

- 投资公司侧栏“预警中心”显示当前用户可见的未处理预警角标。
- 法务工作台展示未处理预警和最近到期事项。
- 登录后进入投资公司应用时拉取未读重要预警，并以弹窗展示；前端每 30 秒刷新角标和新预警。
- 弹窗关闭仅表示已读，不改变业务预警状态。
- 预警的处理、完成和关闭必须在预警中心完成。

## 15. Excel 导入与历史迁移

### 15.1 标准模板

首期提供版本化 `.xlsx` 模板，包含：

- 案件基本信息工作表。
- 当事人工作表。
- 裁判结果工作表。
- 查扣冻资产工作表。
- 清回止损工作表。
- 进展风险工作表。
- 期限事件工作表。
- 填写说明与枚举值工作表。

各子表通过“外部案件编号”关联基本信息。模板不承载二进制附件，历史附件在案件导入后按案件上传。

### 15.2 两阶段导入

1. 上传后只做预检，不写业务表。
2. 规范化日期、金额、状态和空白字符。
3. 输出可导入、警告和错误明细。
4. 重复法院案号列为警告，用户必须逐项确认；缺少案件名称、主状态或必要关联键列为错误。
5. 用户确认后在单一数据库事务中写入案件及全部子表。
6. 任意业务行写入失败则整批回滚，并生成可下载错误报告。
7. 同一批次不能重复确认。

### 15.3 未知历史台账

当前未取得实际历史台账文件，因此本期不猜测旧表头、合并单元格或一格多值规则。取得真实文件后，先制作只读分析报告，再在标准导入服务前增加专用映射器；核心业务表和标准模板不随单个旧文件改变。

## 17. 前端交互

### 17.1 法务工作台

- 指标卡：案件总量、审查立案案件、累计回款、待回款、即将到期资产、未处理预警。
- 时间清单：未来 45 天庭期、未来 45 天查扣冻到期。
- 风险清单：逾期预警、长期无进展案件和即将到期事项。
- 点击卡片或清单跳转到带相同筛选条件的案件或预警列表。

### 17.2 案件列表

筛选项包括案件名称、法院案号、受理法院、当事人、案件状态、标的额区间、负责人、立案日期和更新时间。

列表展示案件编号、案件名称、法院案号、案由、负责人、主状态、标的额、累计回款、最近进展、下一关键期限和预警级别。

### 17.3 预警中心

按预警类型、状态、级别、责任人、截止日期和案件筛选。详情展示触发依据、发送记录和处理历史。处理弹窗要求填写结果并支持上传完成凭证。

### 17.4 统计分析

状态统计表固定显示审查立案、审理中、已判决、执行中、终本、已结案和合计行；列包括数量、占比、标的总额、累计回款、待回款、未处理预警和明细入口。

导出继承当前筛选条件，并在工作簿中记录导出人、导出时间和筛选条件。

## 18. 错误处理与一致性

- 字段校验错误返回对应字段和中文原因。
- 重复法院案号返回可确认警告，不直接阻断保存。
- 越权统一返回 403。
- 已归档对象的写操作返回 409。
- 案件更新携带版本号，版本不一致返回 409 并提示刷新，避免覆盖他人修改。
- 附件先校验权限、类型和大小，文件落盘并计算哈希成功后才创建数据库记录；数据库失败时清理本次文件。
- 删除附件采用逻辑删除并保留审计，不物理覆盖同名文件。
- 导入确认、正式建档和案件状态变更使用数据库事务。
- 钉钉、审计附加记录或后台补偿失败不得破坏主业务事务；失败均产生可追踪状态。

## 19. 安全控制

- 所有附件预览和下载经过鉴权，不暴露服务器真实路径。
- 文件名经过规范化，存储名使用不可预测标识，禁止路径穿越。
- 手机号对非超级管理员脱敏；钉钉投递日志不保存完整手机号。
- Webhook、Secret 和数据库密码仅从环境变量读取。
- 全量导出、归档、解除归档、逻辑删除、附件下载和预警重发均进入操作审计。
- 案件详情和附件响应禁止公共缓存。
- 钉钉消息遵循最小披露原则，不包含敏感案情和资金信息。

## 21. 验收标准

1. 原需求中的基本信息、裁判结果、查扣冻资产、清回止损、当前进展、风险提示和下一步计划均可维护和查询。
2. 普通业务人员和法务风控均可创建案件草稿；信息完整后正式建档并自动生成唯一案件编号，草稿不进入统计和预警。
3. 五类预警按默认日期规则准确生成，同一阶段不重复，终本案件按月循环。
4. 每日 09:00 扫描、期限变更即时生成、逾期每 7 天复提醒均可验证。
5. 钉钉机器人可发送测试消息和真实预警，能按已配置手机号 `@` 责任人，失败有重试和日志。
6. 信息维护超级管理员具备首期最大权限，其他角色无法通过菜单、直接 URL 或 API 绕过数据范围。
7. 案件数量、状态占比、标的总额、累计回款、待回款和预警数与同条件明细及 Excel 导出一致。
8. PDF 和图片可鉴权预览，允许类型的其他材料可鉴权下载；附件操作可审计。
9. 标准 Excel 能完成预检、错误报告和事务导入；未知历史台账在取得样本前不做错误假设。
10. 现有供管公司合同和审批页面的未提交改动不被覆盖，现有功能测试无新增回归。
