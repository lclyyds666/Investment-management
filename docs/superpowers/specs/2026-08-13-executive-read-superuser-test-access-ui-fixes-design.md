# 投资公司高管跨平台只读、超管测试权限与系统界面修复设计

## 背景

统一组织权限上线后存在三类与实际治理要求不一致的问题：

1. 投资公司是母公司，供管公司和基管公司是其二级子公司，但投资公司董事长、总经理、副总经理目前仅能进入投资平台，不能查看两个子公司的事项。
2. `admin` 虽然保持超级管理员身份，但当前权限内核刻意禁止其使用业务功能和办理审批，无法承担全功能测试员职责。
3. 系统管理缺少返回工作平台入口，组织治理名录的双行树节点仍使用固定单行高度，造成名称和编码重叠。

## 权限边界

### 投资公司领导班子

投资公司以下三个岗位属于领导班子：

- `investment.executive.chairman`：董事长
- `investment.executive.general_manager`：总经理
- `investment.executive.deputy_general_manager`：副总经理

三个岗位均获得以下权限：

- 可进入投资公司、供管公司和基管公司三个平台。
- 可查看三个平台内的全部事项和全部业务数据。
- 可下载附件、原始资料和确认文件。
- 可导出报表、台账和列表数据。
- 不可新增、编辑、删除、提交、确认、复核、审批、退回或配置业务数据。
- 当前版本不为三个岗位新增审批节点或审批资格；后续审批流程单独设计。

供管公司现有查看权限使用 `company` 范围、`scope_ref=supplymanagement`。
投资和基管平台目前只有入口权限及在建页面；领导岗位先获得两个平台入口。未来新增其业务权限码时，应沿用同一“查看/下载/导出，不写入、不审批”边界。

### 超级管理员 `admin`

不修改 `admin` 的角色、岗位任职或账号信息。只以现有 `is_superuser=true` 身份提供测试权限：

- 可进入所有平台、所有系统管理页面和所有业务页面。
- 所有后端权限码检查直接通过。
- 所有前端菜单、按钮和路由权限检查直接通过。
- 可执行新增、编辑、删除、提交、下载、导出、确认、复核、审批和退回。
- 可查看所有活动审批任务，并可办理任意当前活动节点，无需拥有该节点岗位任职，也不受同一流程重复参与限制。
- 超管办理仍遵守任务状态、并发 CAS、流程推进和业务状态转换，不可重复完成已完成任务。
- 操作日志继续记录真实用户 `admin`。
- 审批动作快照使用固定治理身份：
  - `organization_code=system.governance`
  - `organization_name=系统治理`
  - `position_code=system.superuser`
  - `position_name=超级管理员`
- 不创建虚假组织、岗位或任职记录。

## 权限内核实现

### 超管短路

后端 `has_permission` 对启用状态的超级管理员返回允许，`allowed_resources` 返回供管平台的全部已注册查看资源。门户应用注册表对超级管理员返回三个平台均可访问；权限快照明确投影全部权限码和资源，供前端按钮与菜单判断使用。

前端 `hasCompany`、`hasResource`、`hasPermission` 在 `isSuperuser` 为真时直接返回允许，避免必须依赖权限快照列出每个码才能显示功能。

### 高管只读模板

授权目录为三个投资公司领导岗位增加：

- `investment.portal.enter`
- `supply.portal.enter`
- `fund.portal.enter`
- 所有 `supply.*.view`
- 所有 `supply.*.export`
- `organization.directory.view`

不授予动作名为 `create`、`update`、`delete`、`submit`、`review`、`approve`、`return` 或 `configure` 的权限。

目录初始化继续采用“只插入缺失授权”的幂等策略，不覆盖管理员手工定制，不删除已有授权。

## 超管审批处理

活动任务查询为超级管理员返回全部当前 `active` 任务。普通用户仍按指定人、共享岗位、任职有效期、外聘服务范围和流程参与冲突规则过滤。

任务办理内核新增明确的超管执行分支：

- 仅当账号启用且 `is_superuser=true` 时可使用。
- 跳过岗位任职和指定人资格检查。
- 保留任务活动状态检查、流程动作允许性、乐观并发控制、退回目标、下一节点激活及最终业务状态更新。
- 写入固定“系统治理 / 超级管理员”快照和真实签名快照。
- 前端待办与审批按钮对超级管理员显示并允许调用原有审批接口。

## 系统管理返回入口

`SystemLayout` 顶部增加“返回工作平台”按钮，路由固定为 `/`。按钮在用户管理、组织通讯录、组织治理、岗位权限、人员任职、操作审计和 AI 会话管理等全部系统页面可见。折叠侧栏和移动端不影响该入口。

## 组织治理名录布局

组织治理页面保持现有双栏结构，但修复树节点尺寸：

- Element Plus 树节点内容高度设为 `auto`，并提供最小高度和上下内边距。
- `.tree-node` 占满可用宽度，名称和编码独立成行。
- 名称与编码使用 `overflow-wrap:anywhere`，长编码自动换行，不挤压相邻节点。
- 节点间增加视觉间距，展开箭头顶部与双行内容对齐。
- 左栏使用 `clamp`/`minmax` 自适应宽度；窄屏继续切换为上下布局。
- “新建组织”按钮与树保持独立间距，不随节点重叠。

## 错误处理与审计

- 超管账号停用时不授予任何测试权限。
- 已完成、已取消、未激活或并发抢先完成的任务仍返回现有冲突/校验错误。
- 普通用户权限行为不变，继续按有效多任职权限并集与数据范围判断。
- 高管只读权限不得通过前端隐藏代替后端校验；写接口必须返回 403。
- 超管所有业务操作继续进入现有操作审计；审批动作进入 `wf_task_action` 和现有业务动作投影。

## 测试与验收

后端测试覆盖：

- 三个投资公司领导岗位均能进入三个平台。
- 三个岗位拥有供管全部查看、下载和导出权限，但没有任何写入或审批权限。
- 超管所有权限码和供管资源检查通过，门户三个平台均可访问。
- 超管不需要新增任职即可看到并办理共享岗位和指定人活动任务。
- 超管审批动作快照记录“系统治理 / 超级管理员”和真实 actor。
- 普通用户的岗位限制、指定人限制和并发冲突测试继续通过。

前端测试覆盖：

- 超管对公司、资源、权限判断全部通过。
- 超管能看到业务动作和审批按钮。
- 系统管理顶部存在“返回工作平台”入口且目标为 `/`。
- 组织治理树节点应用自适应高度、换行和间距样式。
