# 经营分析预测与供应链业务闭环设计

日期：2026-10-10  
状态：已完成交互设计确认，待用户审阅书面规格

## 1. 目标

本次建设同时完成以下目标：

1. 将原一级菜单“经营数据中心”更名为“经营数据”，并设置“数据中心”“分析预测”两个二级菜单。
2. 保留现有经营数据中心页面能力，并将页面名称改为“数据中心”。
3. 新建“分析预测”页面，提供经营情况分析和数据 AI 预测。
4. 在资金管理现有 30 天到期预警基础上增加每日首次登录站内提醒。
5. 在合同管理增加手工录入的合同期限。
6. 在战略总览省份核心经营指标中增加按景区、门票/酒店分别展示的景区完成度。
7. 完善合同、业务审批、资金、发票、文旅台账和数据中心之间的真实业务关联，形成可追溯闭环。

## 2. 已确认的范围与原则

### 2.1 预测范围

- 预测指标：结算金额、景区核销金额、订单量。
- 预测粒度：景区 → 门票/酒店 → 平台。
- 预测周期：支持按月和自定义起止日期；自定义周期最长 90 天。
- 历史数据：只读取已确认的门票、酒店台账。
- 外部数据：当前没有天气和网络资讯 API，不进行联网抓取。
- 影响因素：支持页面表单录入和 Excel 批量导入天气、节假日、活动、资讯影响。
- 结果留存：预测结果只即时展示和导出，不保存预测版本，不进行事后预测偏差追踪。
- 数据不足：优先使用本景区、本业务、本平台历史；不足时按同景区同业务趋势降级估算并标注低置信度。

### 2.2 资金预警范围

- 现有授信、借款提前 30 天页面预警继续保留。
- 新增站内主动提醒，不发送钉钉消息。
- 所有拥有资金管理查看权限的用户均接收提醒。
- 每位用户每天首次登录提醒一次，直至对应事项结清；到期后转为逾期提醒。

### 2.3 合同范围

- 合同期限为自由文本字段，签订日期继续保留。
- 一份合同只能关联一个景区。
- 一份合同可覆盖该景区的一个或多个业务类型、多个台账期次和全部平台。
- 合同更换后，历史台账、发票、审批和资金记录保持原合同快照；新期次使用新合同。

### 2.4 闭环原则

- 审批通过不等于银行已实际收付款。
- 付款审批通过后生成“待资金执行任务”；财务确认真实收付款后才生成资金流水。
- 发票与资金支持多对多核销：多张发票可合并收付款，一张发票也可分次收付款。
- 允许预付款：可先付款审批和实际付款，后补进项发票；系统持续提示未补票金额。
- 台账按景区及业务类型记忆上次关联合同；业务复核可修改；确认台账前必须完成合同关联。
- 闭环异常统一进入“待处理事项”，同时保留各业务页面的上下文提示和处理入口。

## 4. 经营情况分析设计

### 4.1 数据源

- 门票已确认台账。
- 酒店已确认台账。
- 金额直接读取台账中已经落库的景区核销金额和结算金额，不重新执行各景区、平台的解析公式。
- 订单量读取台账订单数量字段。
- 资金占用读取现有净投入、付款日期和回款日期口径。

### 4.2 筛选条件

- 年份或自定义历史周期。
- 景区，支持单选和全部。
- 业务类型：门票、酒店、全部。
- 平台：抖音、美团、携程、同程、票付通及实际已存在的平台。

平台选项从真实台账数据生成，不维护另一套固定平台清单。

### 4.3 分析内容

- 结算金额、景区核销金额、订单量、资金占用核心指标。
- 月度或周期趋势。
- 同比、环比及变化额。
- 景区排名、业务类型排名、平台排名。
- 门票/酒店贡献度、平台贡献度。
- 异常波动识别。
- 异常原因说明和经营建议。

异常波动由确定性规则识别，例如：

- 环比绝对变化超过配置阈值。
- 指标偏离最近周期均值超过标准差阈值。
- 金额增长而订单量显著下降，或订单增长而结算金额显著下降。
- 单个平台贡献度突然集中或下降。

AI 只基于计算结果组织原因解释和经营建议，不直接修改统计金额。DeepSeek 未配置或调用失败时，由规则模板生成说明，页面明确显示所用引擎。

## 5. 数据 AI 预测设计

### 5.1 输入

- 预测方式：按月或自定义周期。
- 自定义周期不得超过 90 天。
- 景区、业务类型、平台。
- 本次手工录入或 Excel 导入的影响因素。

影响因素统一字段：

| 字段 | 说明 |
|---|---|
| 开始日期 | 影响开始日期 |
| 结束日期 | 影响结束日期 |
| 景区 | 可指定景区或全部 |
| 业务类型 | 门票、酒店或全部 |
| 平台 | 指定平台或全部 |
| 因素类型 | 天气、节假日、活动、资讯 |
| 因素名称 | 例如雨天、国庆、平台促销、正向资讯 |
| 影响比例 | 对基线的增减百分比 |
| 备注 | 依据和补充说明 |

Excel 导入和页面表单使用同一套校验。导入模板由系统下载，校验失败时按行返回错误原因，不部分吞错。

### 5.2 历史序列构建

预测最小单元为：

```text
景区 + 业务类型 + 平台
```

已确认台账可能按不规则周期上传。为支持按月和自定义周期预测，系统按台账起止日期将该期结算金额、景区核销金额和订单量均匀分摊为日均序列，再按目标周期重新汇总。没有合法起止日期的历史行不参与预测，并在数据质量提示中列出。

分摊仅用于统计预测，不修改台账原始金额。

### 5.3 基线算法

采用可解释的组合预测，不让大模型直接生成金额：

1. 历史同期：可用时读取上年相同月份或相同日历区间。
2. 近期水平：读取最近三个完整可比周期的加权移动平均。
3. 趋势项：使用最近六个可比周期的线性趋势，限制极端外推。
4. 日历项：按星期结构和法定节假日天数调整订单量与金额日均值。
5. 对可用分量按数据覆盖度归一化加权，任一分量缺失时不以零值参与。

初始权重为历史同期 40%、近期水平 40%、趋势项 20%，后端集中配置，页面在“预测依据”中展示实际使用分量和权重。

金额保留两位小数，订单量按四舍五入生成非负整数。预测不得产生负数。

### 5.4 影响因素叠加

- 多条影响因素按适用日期、景区、业务类型和平台匹配。
- 同一预测日的影响比例采用加法合并，避免多因素连乘造成指数放大。
- 单条影响比例允许范围为 -80% 至 +200%。
- 同一日合并影响限制在 -80% 至 +200%。
- 预测值 = 历史基线 ×（1 + 合并影响比例）。
- 页面展示每个因素对最终结果的增减额。

影响范围及上限由后端校验，前端校验只用于即时提示。

### 5.5 数据不足与置信度

| 条件 | 处理 | 置信度 |
|---|---|---|
| 至少 12 个完整可比周期 | 使用同期、近期和趋势组合 | 高或中 |
| 3 至 11 个完整可比周期 | 使用近期和趋势，可用时加入同期 | 中 |
| 少于 3 个自身周期 | 使用同景区、同业务类型的整体趋势，并按平台已有占比分配 | 低 |
| 同景区、同业务也无可用历史 | 不生成预测 | 无 |

置信度还应考虑历史波动、缺失日期和降级层级。低置信度结果必须显示原因，不与正常预测混为一体。

### 5.6 输出

- 预测结算金额。
- 预测景区核销金额。
- 预测订单量。
- 历史基线、影响因素增减额。
- 高、中、低置信度及原因。
- 预测趋势和上下区间。
- 景区 → 门票/酒店 → 平台分层明细。
- 规则或 AI 生成的经营建议。
- Excel 导出。

预测请求和结果不落库。导出文件由当前请求结果即时生成。

- 未结清且距离到期日 0 至 30 天为即将到期。

- 结清后不再预警。

### 6.2 新增提醒行为

- 登录成功并完成权限加载后，查询当前用户可见的资金预警。
- 仅拥有资金管理查看权限的用户接收。
- 每天首次出现时，以一个汇总弹窗展示所有即将到期和逾期事项。
- 弹窗提供进入资金管理并自动筛选对应状态的入口。
- 提醒展示后写入用户、日期、资金事项和提醒阶段的去重记录。
- 同一事项同一用户同一天不重复弹出；次日继续提醒。
- 新增或变更为预警状态的事项可在当日下一次登录时补充展示。
- 提醒接口失败不得阻塞登录。

## 7. 合同管理扩展

### 7.1 新增字段

- `contract_term`：合同期限，自由文本，允许空值以兼容历史数据。
- `scenic_id`：合同所属景区，新建合同必填；历史合同可为空但不能用于新的闭环业务，直至补充。
- `business_scopes`：合同覆盖的业务类型，多选门票、酒店，至少选择一项。

合同不限制平台；关联景区后可覆盖合同业务范围内的全部平台和多个台账期次。

### 7.2 页面与导出

- 新建、编辑表单显示合同期限、所属景区、业务范围。
- 列表和详情显示合同期限。
- 合同台账和 CSV/Excel 导出包含合同期限、景区、业务范围。
- 下游选择合同时，仅显示状态已审批且景区、业务范围匹配的合同。

## 8. 战略总览景区完成度

### 8.1 计算公式

```text
景区完成度 = 累计景区核销金额 ÷（累计景区核销金额 + 最新景区待核销金额）
```

### 8.2 聚合维度

每个省份点击后，按以下维度独立展示：

```text
景区 + 业务类型（门票/酒店）
```

同一省份存在多个景区时逐个展示；同一景区同时有门票和酒店时分两行展示。

### 8.3 金额口径

- 累计景区核销金额：该景区、该业务类型全部历史台账平台行的景区核销金额之和。
- 最新景区待核销金额：该景区、该业务类型最新一期滚动余额。
- 同一期多个平台共享待核销余额时只取一次，不重复相加。
- 最新一期按周期结束日期、周期开始日期、创建时间和主键顺序确定。
- 分母为 0 时完成度返回空值，前端显示 `—`。
- 其他情况以百分比展示，并保留两位小数。

省级营收、区域利润继续保留；完成度明细在核心经营指标区域中可滚动展示。

## 9. 供应链业务闭环

### 9.1 合同与业务审批强关联

业务审批单和付款审批单新增 `contract_id` 外键，同时继续保存合同编号、客户名称等不可变快照用于历史打印。

- 新建审批单必须从已审批合同中选择，不再只手工输入合同编号。
- 选择合同后自动带出景区、客户和合同编号。
- 销项发票生成的开票审批单继承发票 `contract_id`。
- 合同后续更名或换约不改写历史审批快照。
- 合同删除或失效不得破坏历史单据；已被业务引用的合同原则上只能停用，不能物理删除。

### 9.2 文旅台账与合同关联

新增台账期次关联记录，唯一定位：

```text
景区 + 业务类型 + 台账周期键
```

关联记录保存合同外键、合同编号快照、选择人和选择时间。

- 上传或编辑台账时根据景区和业务类型默认上次合同。
- 业务复核可修改本期合同。
- 提交确认函或批准确认前，必须存在匹配景区和业务范围的已审批合同。
- 台账确认后锁定本期合同；如需更改，应撤销确认、使来源发票失效后重新确认。
- 新合同仅影响新期次，历史期次不批量改写。

### 9.3 台账与发票

已确认台账继续自动生成：

- 进项发票：金额为本期景区核销金额。
- 销项发票：金额为本期结算金额，并按平台生成开票明细。

发票新增 `contract_id`，继承台账期次合同，同时保存合同编号快照。发票仍保留景区、业务类型、期次和来源明细，可从发票下钻至原台账行。

确认后的来源金额发生变化时，沿用现有失效并重新生成机制，但不得静默覆盖已经开票或已经参与资金核销的发票；此时应阻止修改并提示先解除后续关联。

### 9.4 待资金执行任务

新增“待资金执行任务”，用于区分审批授权和实际银行收付款。

#### 付款任务

- 付款审批单最终通过后自动生成。
- 记录审批单、合同、景区、计划金额、已执行金额、未执行金额。
- 状态：待执行、部分执行、已完成、已取消。
- 财务可分次执行，同一审批单生成多笔实际资金流水。
- 实际执行累计不得超过审批金额；超额必须重新审批，不允许直接记账。

#### 回款任务

- 销项发票审批完成且发票上传后生成或激活。
- 记录发票、合同、景区、应收金额、已到账金额、未到账金额。
- 支持一张发票分次回款和多张发票合并到账。

### 9.5 实际资金流水

财务在待执行任务中确认实际收付款时填写：

- 实际日期。
- 实际金额。
- 交易对方。
- 银行流水号。
- 摘要和备注。

系统随后生成资金流水并强关联：

- 待执行任务。
- 合同。
- 付款审批单或回款来源。
- 景区。
- 可选台账期次。

历史手工资金流水继续保留，允许财务后续补充合同和审批关联，但不得自动猜测并批量改写。

### 9.6 发票与资金多对多核销

新增发票资金核销明细表：

| 字段 | 说明 |
|---|---|
| 资金流水 | 实际收款或付款记录 |
| 发票 | 进项或销项发票 |
| 本次核销金额 | 本次用于该发票的金额 |
| 核销人、核销时间 | 审计信息 |

规则：

- 一笔资金流水可分配至多张发票。
- 一张发票可由多笔资金流水逐次核销。
- 单笔资金流水的分配合计不得超过实际金额。
- 单张发票的核销合计不得超过发票金额。
- 进项发票只能由资金支出流水核销。
- 销项发票只能由资金收入流水核销。
- 发票展示未核销、部分核销、已核销三种资金状态。
- 资金流水展示未分配金额。

### 9.7 预付款与后补进项发票

付款审批和实际付款不以进项发票已上传为前置条件。

- 无进项发票时，可按合同发起付款审批并完成实际付款。
- 该资金流水进入“待补票”状态。
- 后续进项发票生成或上传后，财务通过核销明细分配付款金额。
- 未补票金额 = 已付款金额 - 已核销进项发票金额。
- 未补票金额为正时持续进入集中待办。
- 补票不改变原资金流水日期和金额。

### 9.8 合同金额控制

合同详情分别展示：

- 已审批付款金额、待执行付款金额、实际付款金额。
- 已开销项发票金额、已回款金额。
- 未补进项发票金额。

以下任一口径超过合同金额时生成异常提醒：

- 累计已审批付款金额。
- 累计销项发票金额。

考虑合同可能存在补充协议或特殊业务，首期采用预警而非强制拦截。合同金额为 0 或未填写时显示“未配置控制金额”，不误报超额。

### 9.9 集中待处理事项

新增统一“待处理事项”入口，按用户权限聚合：

- 台账待关联合同。
- 待资金执行付款。
- 待确认回款。
- 预付款待补进项发票。
- 发票金额未完全核销。
- 资金流水存在未分配金额。
- 合同金额超额预警。
- 授信或借款即将到期、已经逾期。

每条事项包含类型、景区、合同、金额、发生日期、责任模块、状态和“去处理”链接。列表只做聚合导航，实际修改仍在原业务模块完成。

### 9.10 数据中心全链路追溯

经营数据和战略总览的金额明细支持逐级下钻：

```text
景区
→ 门票/酒店
→ 平台
→ 台账期次与原始台账行
→ 进项/销项发票
→ 发票资金核销明细
→ 实际资金流水与待执行任务
→ 付款/开票审批单
→ 合同与客户
```

数据中心仍以台账为经营指标事实来源，不因发票或资金未完成而改写核销、结算等实际业务金额；后续单据用于追溯和状态核对。

## 10. 权限设计

- 数据中心查看：沿用经营数据查看权限。
- 分析预测查看：沿用经营数据查看权限。
- 影响因素录入、Excel 导入、生成预测：经营数据编辑权限。
- 预测结果导出：经营数据导出权限。
- 合同期限、景区、业务范围：合同新增/编辑权限。
- 台账合同选择：业务复核或现有台账确认权限。
- 待资金执行与发票资金核销：资金管理编辑权限。
- 集中待办查看：按事项对应模块的查看权限过滤。
- 任何跨模块详情接口均再次执行权限校验，不能仅依赖前端隐藏。

## 11. 数据迁移与兼容

### 11.1 合同与审批

- 历史合同的合同期限、景区和业务范围允许为空。
- 历史审批单按唯一合同编号回填 `contract_id`；无法唯一匹配的保持空值并进入待补关联清单。
- 已打印审批快照不因回填而改变。

### 11.2 发票与台账

- 已有来源发票按合同编号唯一匹配回填合同外键。
- 对能从来源销项发票唯一确认合同的历史台账期次，可生成期次合同关联。
- 无法确定合同的历史期次保持原数据，不自动猜测；后续操作前由业务复核补充。

### 11.3 资金流水

- 历史资金流水不自动关联审批、合同或发票。
- 页面标记为“历史未关联”，允许财务逐笔补充。
- 新闭环上线后的实际收付款必须从待执行任务创建，避免继续产生孤立流水。

## 12. 错误处理与数据一致性

- 台账确认、合同关联和发票生成在同一事务内完成，任一步失败则整体回滚。
- 付款审批完成与待执行任务生成在同一事务内完成。
- 实际资金流水、任务执行金额和发票核销明细在同一事务内校验并提交。
- 使用数据库唯一约束防止同一审批重复生成任务、同一期次重复生成发票、同一用户同一天重复提醒。
- 金额并发更新使用行锁或等价的条件更新，防止两名财务人员同时执行导致超额。
- 已开票或已有核销明细的来源数据不得被静默删除。
- Excel 导入限制文件类型、大小和行数；错误按行返回。
- 分析和预测接口对无数据、日期缺失和低置信度使用明确状态，不返回伪造的零值预测。

## 13. 验收标准

### 13.1 导航与经营分析

- 一级菜单显示“经营数据”，二级菜单显示“数据中心”“分析预测”。
- 原经营数据中心功能在“数据中心”完整可用。
- 分析预测可按景区、业务类型、平台和时间筛选。
- 同比、环比、排名、贡献度和异常识别计算正确。

### 13.2 预测

- 同时输出结算金额、景区核销金额和订单量。
- 按景区、门票/酒店、平台分别展示。
- 支持按月和最长 90 天自定义周期。
- 表单和 Excel 影响因素产生相同计算结果。
- 少于三个自身周期时降级并显示低置信度。
- 无可用历史时不生成预测。
- 预测结果可导出但刷新后不从历史记录恢复。

### 13.3 资金预警

- 第 30 天触发，第 31 天不触发。
- 同一用户同一天不重复弹出同一事项。
- 次日继续提醒。
- 结清后停止，过期后转逾期。
- 提醒服务异常不阻塞登录。

### 13.4 合同与完成度

- 合同期限在新建、编辑、列表、详情和导出中一致。
- 新合同必须选择一个景区及至少一个业务类型。
- 完成度能区分多个景区及门票/酒店。
- 待核销余额只取最新一期且不按平台重复累计。
- 分母为 0 时显示 `—`。

### 13.5 业务闭环

- 审批单必须选择真实合同并能反查合同详情。
- 台账确认前必须有匹配合同，确认后发票继承合同。
- 付款审批通过只生成待执行任务，不直接生成资金流水。
- 财务可分次执行付款或回款，累计不超任务金额。
- 发票与资金可以多对多核销，双方剩余金额正确。
- 预付款能够在后续补票后逐步核销，未补票金额实时减少。
- 历史合同替换不改写历史单据。
- 集中待办能列出所有已定义异常并跳转到正确业务页面。
- 数据中心可从聚合金额下钻至台账、发票、资金、审批和合同。

## 14. 不包含内容

- 不接入第三方天气 API 或网络资讯 API。
- 不保存预测版本，不建设预测准确率历史评估。
- 不发送资金到期钉钉提醒。
- 不自动修改历史孤立资金流水。
- 不自动把无法唯一识别的历史合同、台账或发票强行关联。
- 不建设银行直连接口；实际收付款仍由财务确认录入。
