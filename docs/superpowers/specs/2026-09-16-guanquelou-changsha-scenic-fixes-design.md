# 鹳雀楼算法、长沙地图与酒店配置修复设计

日期：2026-09-16

## 目标

完成三项相互关联的文旅景区修复：

1. 鹳雀楼门票台账按平台使用明确的原始金额作为核销与结算基数。
2. 将已经在独立分支开发的长沙动趣王国景区接入当前主分支，并确保湖南省节点在经营大屏地图显示。
3. 景区配置的酒店配置页只展示实际存在酒店业务的景区，移除遵义动物园、南阳森林野生动物世界、鹳雀楼和长沙动趣王国。

门票配置、景区入口、门票台账和其他景区既有算法保持不变。

## 现状与问题

### 鹳雀楼门票算法

当前通用门票计算器把解析出的服务商到账减去抖音服务商佣金后作为出版应得，再分别乘核销率和结算费率。鹳雀楼抖音解析还会从订单实收中扣除软件、达人和撮合经纪服务费。这与本次确认的鹳雀楼业务口径不一致。

美团解析目前只有遵义动物园会把技术服务费计入基数，鹳雀楼仍只使用应付金额。携程和同程已分别使用结算价金额、订单金额，但仍需要通过回归测试固定鹳雀楼专属口径。

### 长沙景区与地图

长沙动趣王国已在 `feature/changsha-dongqu-scenic` 分支中实现景区常量、封面图、后端配置种子和测试，但该提交与当前主分支分叉，尚未进入当前主分支。

经营大屏的 `ScreenMap` 使用前端静态省份坐标生成业务节点和飞线。其坐标表目前没有湖南省，即使数据聚合中出现长沙景区，也会在节点过滤阶段被丢弃。

### 酒店配置

景区配置接口会返回所有景区，酒店配置页直接复用完整列表，因此无酒店业务的景区也会显示默认酒店名称、费率和每间夜服务费。前端景区目录已经使用 `hotelEnabled` 表达酒店业务能力，但配置弹窗尚未使用该字段过滤。

## 方案

### 1. 鹳雀楼平台专属计算基数

在 Excel 解析适配层按 `scenic_id == "guanquelou"` 应用以下规则，并把结果写入既有逐日金额字段：

| 平台 | 景区核销与结算基数 |
| --- | --- |
| 抖音 | 订单实收 |
| 美团 | 应付金额 + 技术服务费 |
| 携程 | 结算价金额 |
| 同程 | 订单金额 |

鹳雀楼抖音不再从订单实收中扣软件服务费、达人服务费、撮合经纪服务费或服务商佣金。美团必须读取技术服务费并按原始正负号与应付金额相加；缺少必要列时返回明确解析错误，避免静默按错误口径生成台账。

通用计算器针对 `guanquelou` 将服务商佣金固定为零，使上传预览、保存、修改费率和基于 `daily_json` 的重新计算保持一致。其他景区继续使用现有佣金和到账规则。

每个平台逐日执行：

```text
景区核销金额 = 当日平台基数 × 核销率
结算金额     = 当日平台基数 × 结算费率
服务费       = 结算金额 − 景区核销金额
```

每日结果按现有规则四舍五入到分后累加。接口字段和数据库结构不变；`supplier_received` 字段对鹳雀楼承载上述平台基数，以兼容现有台账协议。

### 2. 长沙景区接入与地图节点

从 `feature/changsha-dongqu-scenic` 的单一功能提交中移植以下内容到当前主分支，不直接合并分叉分支：

- 前端景区目录增加 `changsha-dongqu` / `长沙动趣王国`，省份为湖南省，仅启用门票业务。
- 后端景区配置种子增加同一 ID 和名称，保持排序为现有景区之后。
- 复用该分支已提供的长沙景区封面图。
- 合并对应前后端景区配置测试。

在 `ScreenMap` 的省份坐标中增加湖南省中心坐标 `[112.94, 28.23]`。经营数据中出现湖南省后，地图应生成湖南业务节点、山东数据中枢到湖南的飞线，并支持点击联动。

### 3. 酒店配置按业务能力过滤

景区配置弹窗继续只请求一次完整配置列表。门票配置页使用全部景区；酒店配置页根据前端景区目录中 `hotelEnabled === true` 的 ID 集合生成独立数据源。

酒店配置页只保留：

- 泉城欧乐堡
- 泉州欧乐堡
- 福州欧乐堡

遵义动物园、南阳森林野生动物世界、鹳雀楼和长沙动趣王国不再显示酒店配置。该过滤只影响酒店配置界面，不删除景区记录，不影响门票配置、门票台账或已存在的历史数据。

## 数据流

### 鹳雀楼上传与重算

1. 上传端点读取鹳雀楼景区配置和对账文件。
2. 解析器按已有规则筛选各平台中的鹳雀楼明细。
3. 解析器按平台提取本设计规定的原始基数并按日聚合。
4. 通用计算器识别 `guanquelou`，不计算服务商佣金，按核销率和结算费率逐日计算。
5. 预览、保存和后续费率编辑复用同一 `daily_json` 与计算入口。

### 长沙地图

1. 长沙景区进入前端景区目录和后端配置目录。
2. 经营数据按景区省份聚合出湖南省数据。
3. `ScreenMap` 根据湖南省坐标生成节点和飞线。

### 酒店配置

1. 配置接口返回完整景区配置。
2. 门票页使用完整列表。
3. 酒店页按景区目录的 `hotelEnabled` 能力集合过滤。

## 错误处理与兼容性

- 鹳雀楼抖音缺少订单实收列、美团缺少应付金额或技术服务费、携程缺少结算价金额、同程缺少订单金额时，解析必须给出包含列名的中文错误。
- 鹳雀楼既有景区筛选规则继续生效，非鹳雀楼行不能进入金额、票数、日期或逐日明细。
- 其他景区不启用本次平台基数规则，避免改变历史计算结果。
- 不新增数据库字段或迁移，不改变 API 返回结构。
- 已保存的鹳雀楼历史行不会自动改写；重新上传原对账文件后按新口径生成。修改只含旧版 `daily_json` 的历史行不能补回原文件中未保存的订单实收，因此不做猜测性迁移。
- 长沙分支内容采用按文件移植，避免把分叉分支中的无关历史带入主分支。
- 酒店配置过滤只改变展示范围，不物理删除配置表中可能存在的字段或历史值。

## 验证方案

### 后端

- 构造包含四个平台的鹳雀楼内存工作簿，断言抖音使用订单实收、美团使用应付金额加技术服务费、携程使用结算价金额、同程使用订单金额。
- 对每个平台分别断言景区核销金额等于基数乘核销率，结算金额等于基数乘结算费率。
- 断言鹳雀楼抖音建议佣金为零，修改费率后从 `daily_json` 重算仍使用同一基数。
- 断言缺少平台必要金额列时解析失败并指出列名。
- 合并长沙景区配置种子测试，确认配置列表顺序和默认门票参数。
- 运行门票解析、通用计算器、景区配置相关测试及完整后端测试。

### 前端

- 合并长沙景区目录测试，确认 ID、名称、省份、封面、门票平台和 `hotelEnabled=false`。
- 为地图坐标或地图选项生成逻辑增加湖南省节点回归测试，确认湖南数据不会被过滤。
- 为景区配置数据筛选增加测试，确认门票页含全部景区，酒店页只含三个启用酒店业务的景区。
- 运行相关 Vitest 测试和前端构建。

## 非目标

- 不修改鹳雀楼以外景区的门票计算口径。
- 不自动重算或覆盖已保存的历史鹳雀楼台账。
- 不新增景区创建后台、动态地图坐标管理或酒店能力数据库字段。
- 不删除无酒店景区的门票配置、景区入口或历史台账。
- 不合并长沙功能分支中的提交历史或其他无关分支改动。
