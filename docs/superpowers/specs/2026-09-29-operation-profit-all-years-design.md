# 经营数据中心毛利润默认全年度设计

## 背景

战略总览与经营数据中心都读取 `/api/v1/operation/financial`，后端返回全部门票、酒店台账的累计指标及逐期明细。战略总览直接展示接口累计值，当前已实现业务毛利润为 `7,393,069.92` 元，即 `739.31` 万元。

经营数据中心加载接口后会自动选择最新年份 `2026`，再用逐期明细重新汇总，因此只显示 `7,333,677.92` 元，即 `733.37` 万元。剩余 `59,392.00` 元属于 `2025` 年，正好构成两页之间的差额。

## 目标

- 经营数据中心默认展示全部年份，与战略总览保持一致。
- 默认已实现业务毛利润显示 `739.31` 万元。
- 保留年份筛选，用户可手工选择 `2026年`、`2025年` 等年份。
- 选择年份后，四项 KPI、两张图表和景区经营数据台账继续同步过滤。
- 清空年份筛选后恢复全部年份累计口径。

## 方案

仅修改经营数据中心前端默认筛选行为：

1. `selectedYear` 初始值继续使用空值，代表“全部年份”。
2. 删除接口加载成功后自动选择最新年份的逻辑。
3. 年份选择框空值状态明确显示“全部年份”。
4. 保留接口返回的 `available_years` 作为年份选项；选择具体年份时继续复用现有 `matchesSharedFilters` 过滤逻辑。
5. 后端聚合、金额公式和接口响应结构均不修改。

该方案使两个页面默认使用同一全量数据源，同时不扩大后端或全局状态管理范围。

## 数据流

`/api/v1/operation/financial` 返回全量累计指标与 `ledger_profit` 逐期明细。经营数据中心收到数据后，在默认空年份条件下汇总全部明细；用户选择具体年份后，前端按 `point.year` 过滤，再将同一结果提供给 KPI、图表和景区台账。

## 异常与兼容

- 若没有可用年份，页面仍显示全部数据或零值，不自动写入年份。
- 无日期的历史台账在“全部年份”中保留；选择具体年份时不计入，与现有行为一致。
- 景区筛选和月份筛选行为不变。
- API 无需迁移，数据库无需调整。

## 测试

更新经营数据中心组件测试，覆盖：

- 页面加载后年份为空，默认累计全部年份。
- 默认 KPI、图表和台账包含 `2025` 与 `2026` 数据。
- 手工选择 `2026年` 后，只显示 2026 年汇总。
- 清空年份后恢复全部年份汇总。
- 年份选项仍包含接口返回的全部可用年份。

## 验收标准

- 战略总览与经营数据中心默认已实现业务毛利润均为 `739.31` 万元。
- 经营数据中心选择 `2026年` 后显示 `733.37` 万元。
- 清空年份筛选后恢复 `739.31` 万元。
- 相关前端测试通过，且不改变其他页面与后端接口行为。
