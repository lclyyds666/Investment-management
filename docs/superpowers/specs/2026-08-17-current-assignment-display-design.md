# 当前有效任职显示修复设计

## 背景与根因

人员任职页面已经通过 `PUT /organizations/users/{user_id}/assignments` 将任职完整保存到 `sys_user_assignment`，门户权限接口也按当前有效任职正确计算访问权限。生产账号 `xulu` 的“法务风控部 / 部门副总监”任职处于启用和有效期内，说明保存与授权链路正常。

显示错误来自另一条旧链路：头部用户标签和个人信息页仍展示 `sys_user.role` 对应的 `role_label`。新建人员的旧角色固定为 `unassigned`，即使已经配置规范任职，界面仍显示“未配置岗位”。

## 目标

- 头部用户标签和个人信息页统一展示当前有效任职。
- 单岗位显示“组织 / 岗位”。
- 多岗位全部显示，使用中文顿号连接并去重。
- 没有当前有效任职时显示“未配置岗位”。
- 超级管理员继续显示“信息维护”。
- 不改变现有数据库结构、任职保存方式或权限计算规则。

## 方案选择

采用前端统一展示适配方案。当前有效任职以门户权限快照中的 `assignments` 为首选来源，因为该接口已经在后端过滤任职状态、生效日期、截止日期以及组织和岗位启用状态。门户上下文尚未完成加载时，使用登录用户的 `assignment_summaries` 作为短暂回退，并在前端再次按状态和日期过滤。

不修改旧 `sys_user.role`，因为该字段仍承担兼容旧审批角色的职责，且无法表达一个用户的多个规范任职。也不把任职反写到旧角色字段，避免多岗位信息丢失。

## 组件与数据流

新增一个无状态的任职显示工具：

1. 接收门户 `assignments` 或用户 `assignment_summaries`。
2. 对带状态和日期的用户摘要筛选当前有效记录；门户快照已由后端筛选，缺少状态字段时视为有效。
3. 将每条记录格式化为“组织名称 / 岗位名称”。
4. 去重后按现有返回顺序使用“、”连接。
5. 超级管理员优先返回“信息维护”；没有有效任职则返回“未配置岗位”。

`UserDropdown` 使用该工具生成头部标签。个人信息页将“角色”字段调整为“当前任职”，并使用相同结果，确保两个位置不会再次出现口径不一致。

## 任职保存边界

超级管理员可在前端修改其他人员任职。保存时后端在单个事务中完整替换目标用户的 `sys_user_assignment` 记录并写入授权审计日志；校验或数据库操作失败时整体回滚。超级管理员自身的信息维护身份继续禁止修改。

本次修复不调整保存接口，仅修正保存成功后的展示来源。

## 异常与兼容处理

- 门户权限快照加载失败时，使用登录响应中的有效任职摘要。
- 任职摘要字段不完整时忽略该条，避免显示 `undefined`。
- 旧账号只有旧角色、没有规范任职时，普通人员显示“未配置岗位”；超级管理员仍显示“信息维护”。
- 权限判断仍只依赖后端当前有效任职和权限授权，不依赖展示文本。

## 测试与验收

- 单岗位账号显示完整“组织 / 岗位”。
- 多岗位账号显示全部去重后的任职。
- 停用、未生效和已过期任职不显示。
- 无任职普通账号显示“未配置岗位”。
- 超级管理员显示“信息维护”。
- 头部和个人信息页显示一致。
- 原有门户权限、路由权限和任职保存测试继续通过。
- 前端全量测试和生产构建通过后部署，并使用生产普通账号验证显示结果与门户访问权限。
